# 21-4 民生機器

**一般の消費者が使う機器**に組み込まれた情報技術を扱う。家電、情報端末、車載機器などが対象になる。

民生機器の組込みシステムには、産業用とは違う制約がある。**価格が厳しく制限され、電池で長時間動く必要があり、専門知識のない人が扱う**。この制約が、使われる技術の選択を決めている。

H21〜R7の午前I・午前IIでは**この小分類からの直接の出題は見当たらなかった**。ただし、組込みシステムの構成要素（→ [6-1 ハードウェア](../06-hardware/6-1-ハードウェア.md)）、IoT向け無線とプロトコル（→ [10-5 ネットワーク応用](../10-network/10-5-ネットワーク応用.md)）、著作権保護技術（→ [8-2 マルチメディア応用](../08-information-media/8-2-マルチメディア応用.md)）といった形で、関連する知識は繰り返し問われている。

## 1. 民生機器の分類

| 分類 | 例 |
| --- | --- |
| AV機器 | テレビ、レコーダ、オーディオ機器 |
| 情報機器 | スマートフォン、タブレット、PC周辺機器 |
| 家庭用機器 | 冷蔵庫、洗濯機、エアコン、給湯器 |
| 車載機器 | カーナビゲーション、ドライブレコーダ、ADAS |
| 健康・医療機器 | 体温計、血圧計、活動量計 |
| ゲーム機器 | 据置型、携帯型 |

これらの多くは**組込みシステム**として実装される。汎用のコンピュータではなく、特定の機能に特化したマイコンとソフトウェアが機器の中で動いている（→ [6-1 ハードウェア](../06-hardware/6-1-ハードウェア.md)）。

## 2. 組込みシステムとしての制約

民生機器の設計を支配する制約を整理する。

| 制約 | 帰結 |
| --- | --- |
| **コスト** | 低価格のマイコン、最小限のメモリを使う。1台あたり数円の差が量産では大きい |
| **消費電力** | 電池駆動なら間欠動作で平均電流を抑える（→ [6-1 ハードウェア](../06-hardware/6-1-ハードウェア.md)） |
| **リアルタイム性** | 決められた時間内に応答しなければならない（→ [5-1 オペレーティングシステム](../05-software/5-1-オペレーティングシステム.md)） |
| **信頼性** | 長期間、無保守で動き続ける必要がある |
| **安全性** | 誤動作が人に危害を及ぼしうる（→ [4-1 システムの構成](../04-system-components/4-1-システムの構成.md) のフェールセーフ） |
| **使いやすさ** | 専門知識のない人が扱う（→ [7-1 ユーザインタフェース](../07-user-interface/7-1-ユーザインタフェース.md)） |

**コスト制約が最も厳しい**のが民生機器の特徴である。産業用機器なら1台数十万円でも成立するが、家電では数千円の製品に収めなければならない。そのため、**処理能力もメモリも極限まで切り詰めた設計**になる。[2-3 プログラム言語](../02-algorithms-and-programming/2-3-プログラム言語.md) で触れたビットマップフォントが組込み機器で今も使われるのは、この制約による。

**出荷後の書換え**が重要になるのも民生機器の特徴である。大量に出荷された後に不具合が見つかっても、回収は現実的でない。[6-1 ハードウェア](../06-hardware/6-1-ハードウェア.md) で見たとおり、ワンチップマイコンにフラッシュメモリが採用される理由はここにある。近年はネットワーク経由でファームウェアを更新する仕組みが一般的になり、セキュリティ上の脆弱性への対応も可能になった（→ [11-4 情報セキュリティ対策](../11-security/11-4-情報セキュリティ対策.md)）。

## 3. 家電のネットワーク化

### 3.1 ホームネットワーク

家庭内の機器をつなぐ技術には、用途に応じた選択肢がある。

| 技術 | 特徴 | 参照 |
| --- | --- | --- |
| 無線LAN | 高速。消費電力は大きい | [10-1 ネットワーク方式](../10-network/10-1-ネットワーク方式.md) |
| **BLE** | 低消費電力。近距離 | [10-5 ネットワーク応用](../10-network/10-5-ネットワーク応用.md) |
| **ZigBee** | 低消費電力。センサネットワーク向け | [10-5](../10-network/10-5-ネットワーク応用.md) |
| **Wi-SUN** | 920MHz帯。スマートメータで採用 | [10-5](../10-network/10-5-ネットワーク応用.md) |
| **PLC** | 電力線を通信に使う。新たな配線が不要 | [10-1](../10-network/10-1-ネットワーク方式.md) |
| **HDMI** | ディジタルAV機器の接続 | [3-4 入出力デバイス](../03-computer-components/3-4-入出力デバイス.md) |

**家電に求められるのは速度より「つながり続けること」と「電池が持つこと」**である。だから無線LANではなくBLEやZigBeeが選ばれる場面が多い。センサが数年間電池交換なしで動くことのほうが、通信速度より価値をもつ。

### 3.2 コンテンツ保護

AV機器では、著作権保護技術が必須になる（→ [8-2 マルチメディア応用](../08-information-media/8-2-マルチメディア応用.md)）。

| 技術 | 保護する対象 |
| --- | --- |
| **CPRM** | SDメモリカードなど記録型メディア |
| **DTCP** | 機器間の伝送（IEEE 1394、LAN） |
| **HDCP** | HDMIなどの映像出力 |

録画機器では、**記録（CPRM）、機器間転送（DTCP）、表示出力（HDCP）のすべての経路で保護**しなければ意味がない。どこか1か所でも無防備なら、そこから複製される。**経路全体を守る必要がある**というのは、[11-4 情報セキュリティ対策](../11-security/11-4-情報セキュリティ対策.md) で見た多層防御と同じ考え方である。

### 3.3 民生機器とIoTのセキュリティ

家電やネットワークカメラがインターネットにつながることで、新しいリスクが生じた。

- **初期パスワードのまま使われる**ことが多く、容易に乗っ取られる
- **保守されないまま長期間使われる**ので、脆弱性が放置される
- 乗っ取られた機器が**DDoS攻撃の踏み台**になる（→ [11-1 情報セキュリティ](../11-security/11-1-情報セキュリティ.md) のボットネット）

**利用者が「コンピュータを使っている」と認識していない**ことが、この問題を難しくしている。PCならセキュリティ更新を意識するが、冷蔵庫やカメラでは意識されない。だから**出荷時に安全な設定にしておく、自動更新を標準にする**といった、利用者に依存しない対策が求められる。

## この章のまとめ

- 民生機器の設計は**コスト、消費電力、リアルタイム性、信頼性、安全性、使いやすさ**の制約を同時に満たす必要がある。なかでも**コスト制約が最も厳しい**。
- 出荷後の回収が現実的でないため、**フラッシュメモリによる書換えとネットワーク経由の更新**が重要になる。
- 家電のネットワーク化では、速度より**低消費電力と到達性**が優先される。
- コンテンツ保護は**記録・伝送・出力のすべての経路**を守らなければ意味がない。
- IoT化した民生機器は、**利用者がコンピュータだと認識していない**ため、利用者に依存しない安全策が求められる。
