# 21-3 eビジネス

インターネットを使った**商取引と事業の形態**を扱う。

eビジネスが成立する条件は、**取引の相手が見えなくても安心して取引できる**ことである。対面であれば相手の顔と店舗を見て判断できるが、ネット上ではそれができない。だから、データ形式を揃える規約（EDI）、第三者が仲立ちする仕組み（エスクロー）、分散した事業者をまとめる仕組み（アグリゲーション）といった、信頼を補う仕掛けが発達した。

午前Iの問28前後から出題される。16年で4問。

## 1. 取引形態の分類

**誰と誰の取引か**で分類する。

| 略語 | 取引の当事者 | 例 |
| --- | --- | --- |
| **BtoB** | 企業間 | 部品の調達、EDIによる受発注 |
| **BtoC** | 企業と消費者 | ECサイト |
| **CtoC** | 消費者間 | フリマアプリ、ネットオークション |
| **BtoE** | 企業と従業員 | 社内向け福利厚生サービス |
| **GtoC** | 行政と市民 | 電子申請（→ [21-1 ビジネスシステム](21-1-ビジネスシステム.md)） |

**CtoCで特に信頼の担保が問題になる**。企業が相手なら実体があり、法的な責任追及も可能だが、個人同士では「代金を払ったのに商品が届かない」というリスクが現実的になる。これに対処するのが [3. eビジネスのサービス形態](#3-eビジネスのサービス形態) のエスクローサービスである。

## 2. EDI

**EDI（Electronic Data Interchange、電子データ交換）**は、**企業間で取引データを標準的な形式でやり取りする**仕組みである。

### 2.1 4つの規約

EDIを実施するには、4階層の取決めが必要になる。

| 規約 | 定めるもの |
| --- | --- |
| **情報伝達規約** | **通信手順**。どのプロトコルで送るか |
| **情報表現規約** | **メッセージの形式**。データの項目、桁数、コード体系 |
| **業務運用規約** | **システムの運用時間**、障害時の対応、検収のタイミング |
| **取引基本規約** | **企業間の取引の契約内容**。法的な効力、責任の範囲 |

> EDIを実施するための**情報表現規約**で規定されるべきものはどれか。

答えは **メッセージの形式**である。

4つの規約は**層をなしている**と考えると判別しやすい。

```
取引基本規約    法律・契約の層      「この取引は法的にどう扱うか」
  ↓
業務運用規約    業務の層            「いつ運用し、障害時にどうするか」
  ↓
情報表現規約    データの層          「メッセージをどういう形式で表すか」
  ↓
情報伝達規約    通信の層            「どの手順で送るか」
```

この構造は [10-2 データ通信と制御](../10-network/10-2-データ通信と制御.md) のOSI基本参照モデルと同じ発想である。**下の層が上の層を支え、各層は独立して決められる**。通信手順をインターネットに変えても、メッセージ形式や契約内容を変える必要はない。

**情報表現規約の標準化が重要なのは、形式が揃っていなければ自動処理ができない**からである。取引先ごとに形式が違えば、相手の数だけ変換プログラムが要る。業界標準を定めることで、この負担をなくせる。

> **出題** EDIの情報表現規約: H22午前I問28、H25午前I問28

## 3. eビジネスのサービス形態

### 3.1 アグリゲーションサービス

> **アグリゲーションサービス**に関する記述として適切なものはどれか。

答えは、

> **分散的に存在する事業者、個人や機能への一括的なアクセスを顧客に提供し、比較、まとめ、統一的な制御、最適な組合せなどワンストップでのサービス提供を可能にするサービス。**

**「分散しているものを一か所にまとめる」**のがアグリゲーション（aggregation＝集約）である。複数の金融機関の口座残高を1画面で見られるサービス、複数の航空会社の運賃を比較できるサービスなどが該当する。

価値は**利用者の手間を減らす**ことにある。各社のサイトを個別に見て回り、条件を揃えて比較する作業を、サービス側が肩代わりする。

誤答として並ぶ他のサービス形態との区別を押さえる。

| 記述 | 実際は何か |
| --- | --- |
| 店舗やECサイトなどあらゆる顧客接点をシームレスに統合し、どの接点でも最適な購買体験を提供する | **オムニチャネル** |
| 物品の売買に際し、**信頼のおける中立的な第三者が契約当事者の間に入り、代金決済等の安全性を確保する** | **エスクローサービス** |
| **分散的に存在する事業者や機能への一括的なアクセスを提供し、ワンストップでのサービス提供を可能にする** | **アグリゲーションサービス** |
| 本部と契約した加盟店が、本部に対価を支払い、販売促進や確立したサービス・商品を使う権利をもらう | **フランチャイズ** |

**アグリゲーションとオムニチャネルは紛らわしい**。アグリゲーションは**複数の事業者**をまとめ、オムニチャネルは**1社の複数の販売接点**を統合する。誰のものをまとめるかが違う。

**エスクローサービス**は [1. 取引形態の分類](#1-取引形態の分類) で触れたCtoC取引の信頼問題への解である。買い手は代金を第三者に預け、商品の到着を確認してから第三者が売り手に支払う。これにより、**互いを知らない個人同士でも取引が成立する**。

### 3.2 その他のeビジネス用語

| 用語 | 内容 |
| --- | --- |
| ロングテール | 売れ筋でない多数の商品の売上合計が、売れ筋の売上に匹敵する現象 |
| アフィリエイト | 成果報酬型の広告 |
| オプトイン／オプトアウト | 広告メールの送信について、事前承諾を得る方式／拒否の機会を与える方式 |
| **クラウドファンディング** | 不特定多数から少額ずつ資金を募る |
| シェアリングエコノミー | 遊休資産を個人間で貸借する |

**ロングテールがネット販売で成立するのは、陳列スペースの制約がないから**である。実店舗では売れ筋を並べるしかないが、ネットなら在庫を1点ずつ持つだけで無数の商品を扱える。[9-5 データベース応用](../09-database/9-5-データベース応用.md) のレコメンド（推薦）機能が、この「埋もれた商品」を見つけ出す役割を担う。

> **出題** アグリゲーションサービス: R3午前I問28、R5午前I問28

## 4. 電子決済

| 方式 | 内容 |
| --- | --- |
| クレジットカード決済 | 後払い。与信審査が前提 |
| デビットカード決済 | 即時引落し |
| 電子マネー | 事前にチャージ（プリペイド）または後払い |
| **QRコード決済** | スマートフォンで読み取って決済 |
| **暗号資産** | ブロックチェーンに基づく |

### 4.1 決済における本人認証

eビジネスの決済では、**本人であることをどう確かめるか**が中心的な課題になる。カード番号を知っているだけで決済できれば、番号が漏れた時点で不正利用される。

[11-1 情報セキュリティ](../11-security/11-1-情報セキュリティ.md) で扱った**3Dセキュア2.0**は、この課題への現在の答えである。常に追加認証を求めるのではなく、**取引履歴やデバイス情報からリスクを判定し、高リスクのときだけ追加認証を行う**（リスクベース認証）。安全性と利便性を両立させる考え方になっている。

### 4.2 ブロックチェーン

**ブロックチェーン**は、**取引記録を時系列にチェーン状に結び、ネットワーク上の複数のノードで共有する**ことで改ざんを困難にする技術である（→ [11-1 情報セキュリティ](../11-security/11-1-情報セキュリティ.md) の前方秘匿性の誤答選択肢として登場する）。

改ざんが困難なのは2つの性質による。

- **各ブロックが前のブロックのハッシュ値を含む**ので、過去の記録を書き換えると以降のすべてのハッシュ値が合わなくなる（→ [1-3 情報に関する理論](../01-basic-theory/1-3-情報に関する理論.md)）
- **多数のノードが同じ記録を持つ**ので、1か所を書き換えても他と食い違う

**中央の管理者を置かずに信頼を成立させる**という点が、この技術の本質である。[1. 取引形態の分類](#1-取引形態の分類) で述べた「相手が見えなくても安心して取引できるようにする」という課題に対し、エスクローが「信頼できる第三者を置く」解だとすれば、ブロックチェーンは「第三者を不要にする」解にあたる。

## この章のまとめ

- 取引形態は**誰と誰か**で分類する。**CtoCでは信頼の担保が課題**になる。
- EDIの4規約は**取引基本（契約）→ 業務運用（運用時間）→ 情報表現（メッセージの形式）→ 情報伝達（通信手順）**の層構造。OSI参照モデルと同じ発想で、各層を独立に決められる。
- **アグリゲーションは複数の事業者をまとめる、オムニチャネルは1社の複数接点を統合する、エスクローは第三者が決済を仲立ちする、フランチャイズは本部と加盟店の契約**。
- **ロングテールがネットで成立するのは陳列スペースの制約がないから**。
- **ブロックチェーンは、中央の管理者を置かずに改ざん困難性を成立させる**。エスクローとは逆方向の解にあたる。
