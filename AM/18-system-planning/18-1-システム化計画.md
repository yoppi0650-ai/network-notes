# 18-1 システム化計画

情報システムを**企画する最初の段階**を扱う。何のために作るのか、本当に実現できるのか、どれだけの費用と期間がかかるのかを検討する。

この工程の重要性は、**ここでの判断の誤りは後工程では取り返せない**ことにある。設計やプログラミングの誤りは直せるが、「そもそもこのシステムは必要なかった」という誤りは、完成させてから気づいても手遅れである。だからこの段階では、作り方ではなく**作るべきかどうか**を問う。

午前Iの問25前後から出題される。16年で2問。

## 1. システム化構想の立案

**システム化構想**は、企画プロセスの最初の活動である。**経営課題を把握し、情報技術でどう解決するかの方向性を定める**。

> ある企業が、AIなどの情報技術を利用した自動応答システムを導入して、コールセンタにおける顧客対応を無人化しようとしている。この企業が、**システム化構想の立案プロセスで行うべきこと**はどれか。

答えは、

> **AIなどの情報技術の動向を調査し、顧客対応における省力化と品質向上など、競争優位を生み出すための情報技術の利用方法について分析する。**

誤答と並べると、**工程の違い**がはっきりする。

| 記述 | どの工程か |
| --- | --- |
| **情報技術の動向を調査し、競争優位を生み出す利用方法を分析する** | **システム化構想の立案** |
| ソフトウェア製品やシステムの信頼性、効率性など**品質に関する要件を定義する** | **要件定義**（非機能要件 → [18-2 要件定義](18-2-要件定義.md)） |
| 必要なシステム機能及び能力などの**システム要件を定義し、システム要素に割り当てる** | **システム要件定義・システム方式設計**（→ [12-1 システム・ソフトウェア要件定義](../12-system-development/12-1-システム-ソフトウェア-要件定義.md)） |
| ソフトウェアの**要件定義を行い、実現方式やインタフェース設計を行う** | **ソフトウェア要件定義・設計**（→ [12-2 設計](../12-system-development/12-2-設計.md)） |

**構想の段階では、まだ「何を作るか」も決まっていない**。決めるのは「どういう方向で経営課題を解決するか」である。誤答はすべて、方向が定まった後の具体化にあたる。

キーワードは**「競争優位」「技術動向の調査」「利用方法の分析」**である。経営の視点から技術を見る段階だと理解すればよい。

> **出題** システム化構想の立案: H30午前I問25

## 2. システム化計画の策定

構想で定めた方向を、**具体的な計画に落とし込む**のがシステム化計画である。

| 検討項目 | 内容 |
| --- | --- |
| 対象業務の明確化 | どの業務をシステム化するか |
| システム化の範囲と機能の概要 | 何をどこまで作るか |
| **開発スケジュール** | いつまでに作るか |
| **概算コストと投資効果** | いくらかかり、どれだけの効果があるか |
| 要員・体制 | 誰が作り、誰が使うか |
| リスクの分析 | 何が障害になりうるか |
| 適用評価 | パッケージ製品で代替できないか |

**この段階の見積りは精度が低い**ことを前提にしなければならない。要件が固まっていないので、正確な工数は出せない。だからこそ、**幅をもたせた見積りと、前提条件の明示**が重要になる。「この前提のもとでこの程度」と示しておけば、前提が崩れたときに見直せる。

システム開発計画の策定における統制の観点（複数の代替案を作成して比較検討する、など）は [16-1 システム監査](../16-system-audit/16-1-システム監査.md) で扱う。

## 3. フィージビリティスタディ

> **フィージビリティスタディ**の説明はどれか。

答えは、

> **企業が新規事業立ち上げや海外進出する際の検証、公共事業の採算性検証、情報システムの導入手段の検証など、実現性を調査・検証する投資前評価のこと。**

**「実現性」「投資前評価」**がキーワードである。実行可能性調査とも呼ばれる。

検証する観点は多岐にわたる。

| 観点 | 問い |
| --- | --- |
| 技術的実現性 | その技術で本当に実現できるか |
| 経済的実現性 | 採算が合うか |
| 運用面の実現性 | 運用体制を確保できるか |
| 法的・制度的実現性 | 法規制に抵触しないか |
| 期間の実現性 | 必要な時期に間に合うか |

**「投資前」に行う**ことに意味がある。投資してから「できなかった」と分かるのでは損失が大きい。比較的少ない費用で調査し、見込みがなければ着手しないという判断をするための活動である。

誤答として並ぶ手法との区別を押さえる。

| 記述 | 実際は何か |
| --- | --- |
| **実現性を調査・検証する投資前評価** | **フィージビリティスタディ** |
| 専門家グループの直観的意見や経験的判断を、反復型アンケートで組織的に集約・洗練して収束する | **デルファイ法**（→ [20-1 技術開発戦略の立案](../20-technology-strategy-management/20-1-技術開発戦略の立案.md)） |
| 会議の参加メンバーが自由奔放にアイディアを出し合い、連想によってさらに多数のアイディアを生み出す集団思考法 | **ブレーンストーミング** |
| 商品が市場に投入されてから姿を消すまでを、導入期・成長期・成熟期・衰退期の4段階で表現する | **プロダクトライフサイクル**（→ [19-2 マーケティング](../19-business-strategy-management/19-2-マーケティング.md)） |

4つはいずれも企画段階で使われる手法だが、**フィージビリティスタディだけが「実現できるかの検証」**であり、他は発想法や分析枠組みである。

> **出題** フィージビリティスタディ: R6午前I問27

## この章のまとめ

- **システム化構想では「何を作るか」ではなく「どういう方向で経営課題を解決するか」を決める**。技術動向の調査と、競争優位を生む利用方法の分析が中心になる。
- **システム化計画の見積りは精度が低いことを前提に、幅と前提条件を明示する**。
- **フィージビリティスタディは「実現性の投資前評価」**。技術・経済・運用・法規制・期間の各面から検証し、見込みがなければ着手しないという判断をするための活動である。
