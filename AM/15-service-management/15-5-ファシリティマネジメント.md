# 15-5 ファシリティマネジメント

ITシステムを支える**設備・施設**の管理を扱う。電源、空調、建物、入退室管理などが対象になる。

ソフトウェアやネットワークをどれだけ堅牢に作っても、**電源が落ちれば止まり、空調が止まれば機器が壊れ、人が侵入すればデータが持ち去られる**。ファシリティマネジメントは、情報システムが依存している物理的な土台を守る領域である。

H21〜R7の午前I・午前IIでは**この小分類からの直接の出題は見当たらなかった**。ただし、テンペスト対策（→ [11-4 情報セキュリティ対策](../11-security/11-4-情報セキュリティ対策.md)）や保守体制とMTTR（→ [4-2 システムの評価指標](../04-system-components/4-2-システムの評価指標.md)）といった形で、関連する知識は問われている。

## 1. 電源設備

| 設備 | 役割 |
| --- | --- |
| **UPS**（無停電電源装置） | 停電時に**短時間**電力を供給する。安全に停止させる時間を稼ぐ |
| 自家発電装置 | 長時間の停電に備える。UPSから引き継ぐ |
| 無停電電源系統 | 重要機器用に系統を分ける |
| サージプロテクタ | 落雷などによる過電圧から機器を守る |

**UPSの目的は「停電中も動かし続けること」ではない**という点が実務上重要である。一般的なUPSが供給できるのは数分から十数分であり、その間に**安全にシャットダウンする**か、**自家発電装置が立ち上がるまでをつなぐ**のが役割になる。処理の途中で電源が落ちればデータが壊れうるので、「止めるための時間」を確保すること自体に価値がある。

[10-1 ネットワーク方式](../10-network/10-1-ネットワーク方式.md) で見たPoEは、給電元のスイッチをUPSにつなげば、末端の無線LANアクセスポイントやIP電話まで無停電化できるという利点をもつ。電源設備の設計はネットワーク設計とも関わる。

## 2. 空調と環境

| 対策 | 目的 |
| --- | --- |
| 空調（温度・湿度の管理） | 機器の熱暴走と結露を防ぐ |
| ホットアイル／コールドアイル | ラックの向きをそろえ、冷気と暖気を分離して冷却効率を上げる |
| 免震・耐震 | 地震による機器の転倒・破損を防ぐ |
| 消火設備 | ガス消火（水をかけると機器が壊れるため） |
| 防水・止水 | 水漏れや浸水を防ぐ |

**データセンタの消火に水を使わない**のは、消火できても機器がすべて失われるからである。不活性ガスによる消火が用いられる。このように、一般の建物の設備基準がそのままは当てはまらないのがファシリティマネジメントの特徴になる。

## 3. 物理的セキュリティ

情報セキュリティの対策は、論理的な対策だけでは完結しない。

| 対策 | 内容 |
| --- | --- |
| **入退室管理** | ICカード、生体認証による認証（→ [11-1 情報セキュリティ](../11-security/11-1-情報セキュリティ.md)） |
| **アンチパスバック** | 入室記録のない者の退室を認めない。共連れを防ぐ |
| **インターロック（二重扉）** | 一方が閉じないともう一方が開かない。共連れを防ぐ |
| 監視カメラ | 記録と抑止 |
| 施錠管理 | ラック単位の施錠 |
| クリアデスク・クリアスクリーン | 書類や画面を放置しない |
| **電磁波の遮へい** | **テンペスト攻撃**への対策（→ [11-4 情報セキュリティ対策](../11-security/11-4-情報セキュリティ対策.md)） |

**共連れ（ピギーバック）**は、認証した人の後ろについて無認証で入室する行為である。認証装置をいくら強化しても、扉が開いている間に続いて入られれば意味がない。**アンチパスバックとインターロックは、この「認証の抜け道」を塞ぐための仕組み**である。

同じ構造の問題は論理的なセキュリティにもある。認証を強くしても、セッションを乗っ取られれば無意味になる（→ [11-5 セキュリティ実装技術](../11-security/11-5-セキュリティ実装技術.md)）。**認証そのものより、認証の前後の抜け道が狙われる**という点は共通している。

## 4. データセンタの評価

データセンタの可用性を段階的に評価する指標として、**ティア（Tier）**がよく参照される。

| 段階 | おおよその特徴 |
| --- | --- |
| ティア1 | 冗長化なし。保守時には停止する |
| ティア2 | 一部の設備を冗長化 |
| ティア3 | 保守作業を停止せずに行える（コンカレントメンテナビリティ） |
| ティア4 | 単一障害点がなく、障害が起きても継続できる |

段階が上がるほど可用性は高まるが、**設備投資も運用コストも跳ね上がる**。[15-1 サービスマネジメント](15-1-サービスマネジメント.md) で述べたとおり、サービスレベルはコストとの兼ね合いで決めるものであり、データセンタの選択も同じ判断になる。

また、近年は可用性だけでなく**環境性能**も評価軸になっている。**PUE（Power Usage Effectiveness）**は、データセンタ全体の消費電力をIT機器の消費電力で割った値で、**1.0に近いほど空調などの付帯設備による消費が少なく効率がよい**ことを示す。

## この章のまとめ

- **UPSの役割は「動かし続けること」ではなく「安全に止める時間、または自家発電に引き継ぐ時間を稼ぐこと」**。
- データセンタの消火に水を使わないなど、**一般の建物の基準がそのままは当てはまらない**。
- **共連れを防ぐのがアンチパスバックとインターロック**。認証そのものより、認証の抜け道が狙われる。
- データセンタの可用性は**ティア**で段階評価され、上がるほどコストも跳ね上がる。環境性能の指標が**PUE**で、1.0に近いほど効率がよい。
