# 16-1 システム監査

情報システムを**独立した立場から点検・評価し、改善を助言する**活動を扱う。

システム監査の存在意義は**独立性**にある。作った人、運用している人が自分で点検しても、自分の判断の前提そのものを疑うのは難しい。利害関係のない第三者が、定められた基準に照らして評価するからこそ、経営者はその結果を信頼できる。本章で繰り返し現れる「監査人は指示も実施もしない、助言するだけ」という制約は、すべてこの独立性を守るためのものである。

午前Iの問21・問22前後から出題される。**16年で23問**と、マネジメント系・ストラテジ系のなかで最多である。

## 1. システム監査の目的と独立性

### 1.1 点検・評価の対象

> システム監査基準（令和5年）によれば、システム監査において監査人が一定の基準に基づいて総合的に点検・評価を行う対象とするものは、情報システムの**マネジメント**、**コントロール**と、あと一つはどれか。

答えは **ガバナンス**である。

3つは階層をなしている。

| 対象 | 意味 |
| --- | --- |
| **ガバナンス** | 経営者が情報システムを**統治する**仕組み。方向付けと監督 |
| **マネジメント** | 定められた方針に従って**管理する**活動 |
| **コントロール** | 業務の中に組み込まれた**統制**（入力チェック、承認手続など） |

令和5年の改訂で**ガバナンスが明示された**のは、情報システムが経営そのものに直結するようになり、**現場の統制だけでなく経営者の関与を評価する必要が出てきた**ためである。誤答に並ぶコンプライアンス、サイバーレジリエンス、モニタリングは、いずれも評価の観点ではあっても、この3つの並びには入らない。

### 1.2 監査人の責任と独立性

> システム監査人が負う責任はどれか。

答えは **監査報告書に記載した監査意見**である。

システム監査人の責任範囲を正確に押さえることが、この分野の多くの設問を解く鍵になる。

| 事項 | 監査人が責任を負うか |
| --- | --- |
| **監査報告書に記載した監査意見** | **負う** |
| 監査結果の外部への開示 | 負わない（開示の判断は依頼者である経営者） |
| 監査対象システムの管理 | 負わない（それは被監査部門の責任） |
| 監査報告会で指摘した問題点の改善 | **負わない**（改善を実施するのは被監査部門） |

**監査人は「評価して意見を述べる」ところまでが責任範囲**である。改善の実施まで負えば、次の監査で**自分がやったことを自分で評価する**ことになり、独立性が失われる。

この原則は、後述するフォローアップでの行動（→ [6. フォローアップ](#6-フォローアップ)）にも一貫して現れる。

> **出題** システム監査人の責任: H24午前I問22 ｜ システム監査の点検・評価対象: R6午前I問21

## 2. 監査の流れ

```mermaid
graph LR
  A["監査計画の策定"] --> B["予備調査"] --> C["本調査"] --> D["評価・結論"] --> E["監査報告"] --> F["フォローアップ"]
```

### 2.1 予備調査

**予備調査**は、本調査の前に**監査対象の実態を把握する**ための調査である。

> システム監査基準（平成30年）における**予備調査**についての記述として、適切なものはどれか。

答えは、

> **監査対象部門の事務手続やマニュアルなどを通じて、業務内容、業務分掌の体制などを把握する。**

また、

> **被監査部門から事前に入手した資料を閲覧し、監査対象の実態を明確に把握する。**

も予備調査の作業である。

誤答として並ぶ記述を確認すると、予備調査の位置づけがはっきりする。

| 記述 | 実際は何か／なぜ誤りか |
| --- | --- |
| 監査テーマに基づいて監査項目を設定し、監査手続を策定して個別監査計画書に記載する | **監査計画の策定**（予備調査より前） |
| 経営トップにヒアリングし、監査テーマを設定する | **監査計画の策定** |
| 個別監査計画を策定するために、監査スケジュールを被監査部門と調整する | 監査計画の策定 |
| 監査の結論を裏付けるために、十分な監査証拠を入手する | **本調査**の目的である |
| 監査対象の実態を把握するために、**必ず現地に赴いて**実施する | **現地調査は必須ではない**。資料の閲覧でも把握できる |
| 調査の範囲は、**監査対象部門だけに限定する** | 関連部門の状況も把握対象になりうる |

**予備調査は「実態を知る」段階、本調査は「証拠を集める」段階**という区別で判別できる。

予備調査が必要なのは、**対象を知らないまま監査手続を決めても的外れになる**からである。業務の流れも体制も分からずにチェックリストを作れば、重要な論点を外す。

### 2.2 監査手続

> システム監査における**「監査手続」**として、最も適切なものはどれか。

答えは、

> **監査項目について、十分かつ適切な証拠を入手するための手続**

である。

誤答との区別を押さえる。

| 記述 | 実際は何か |
| --- | --- |
| 監査計画の立案や監査業務の進捗管理を行うための手続 | 監査業務の管理 |
| 監査結果を受けて、監査報告書に結論や指摘事項を記述する手続 | 監査報告 |
| **監査項目について、十分かつ適切な証拠を入手するための手続** | **監査手続** |
| 監査テーマに合わせて監査チームを編成する手続 | 監査体制の整備 |

**「監査手続」は証拠を集めるための手順**を指す。監査全体の進め方ではない。

> **出題** 予備調査: H27午前I問21、R5午前I問21 ｜ 監査手続: R7午前I問22

## 3. 監査技法

監査証拠を入手する方法が**監査技法**である。

| 技法 | 内容 |
| --- | --- |
| **インタビュー法** | **システム監査人が、直接、関係者に口頭で問い合わせ、回答を入手する** |
| **チェックリスト法** | **システム監査人が作成した質問書**に回答を求める |
| ドキュメントレビュー法 | 資料及び文書類を入手し、内容を点検する |
| **現地調査法** | システム監査人が監査対象部門に**直接赴いて、自ら観察・調査する** |
| **ウォークスルー法** | **データの生成から入力、処理、出力、利活用までのプロセス、及び組み込まれている一連のコントロールを確認する** |
| **テストデータ法** | テストデータを監査対象プログラムで処理し、期待した結果が出力されるかを確かめる |
| 並行シミュレーション法 | 監査人が用意したプログラムで同じデータを処理し、結果を比較する |
| 監査モジュール法 | 監査用のモジュールを業務プログラムに組み込んでおく |
| **コンピュータ支援監査技法（CAAT）** | 監査用のソフトウェアを使ってデータを分析する |

### 3.1 ウォークスルー法

> システム監査における**ウォークスルー法**の説明として、適切なものはどれか。

答えは、

> **データの生成から入力、処理、出力、利活用までのプロセス、及び組み込まれている一連のコントロールを確認する。**

**「データの流れを最初から最後まで追う」**のがウォークスルー法である。1件のデータを選び、それが生まれてから使われるまでを順に追跡し、**途中にどんな統制があり、それが機能しているか**を確認する。

部分だけを見ても分からないことがある、というのがこの技法の前提にある。各工程が個別には正しくても、工程と工程のつなぎ目で統制が抜けていることがある。通しで追えばそれが見つかる。

誤答として並ぶ技法との区別も確認する。

| 記述 | 技法 |
| --- | --- |
| 機密データの保管状況に関する資料及び文書類を入手し、内容を点検する | **ドキュメントレビュー法** |
| システムの運用状況について、関係者に口頭で問い合わせ、回答を入手する | **インタビュー法** |
| **データの生成から利活用までのプロセスとコントロールを確認する** | **ウォークスルー法** |
| テストデータを監査対象プログラムで処理し、期待した結果が出力されるかを確かめる | **テストデータ法** |

### 3.2 技法に関する誤った記述

> システム監査基準（平成30年）における監査手続の実施に際して利用する技法に関する記述のうち、適切なものはどれか。

答えは **インタビュー法の定義**（直接、関係者に口頭で問い合わせ、回答を入手する）である。

誤答が、それぞれ技法の運用に関する誤解を示している。

| 記述 | なぜ誤りか |
| --- | --- |
| 現地調査法は、当該部門の**業務時間外に実施しなければならない** | **そのような制約はない**。むしろ業務の実態を観察するには業務時間中のほうが適切な場合が多い |
| コンピュータ支援監査技法は、**専用ソフトウェアによらなければならない** | 表計算ソフトなど汎用のツールでも実施できる。**専用ソフトに限定されない** |
| チェックリスト法とは、**監査対象部門がチェックリストを作成**し、見解を取りまとめた結果を監査人が点検する技法 | **チェックリストを作成するのは監査人**である。被監査部門が作れば、監査人が確かめたい観点が落ちる |

**「〜しなければならない」「〜によらなければならない」という断定が入っている選択肢は疑う**のが、この種の設問に対する有効な構えである。監査基準は技法の選択を監査人の判断に委ねており、過度な制約は課していない。

> **出題** 監査技法: R1午前I問22、R5午前I問22 ｜ ウォークスルー法: R7午前I問21

## 4. 監査証拠とサンプリング

### 4.1 監査証拠の入手と評価

> 監査証拠の入手と評価に関する記述のうち、システム監査基準（平成30年）に照らして、**適切でないもの**はどれか。

適切でないのは、

> **アジャイル手法を用いたシステム開発プロジェクトにおいては、管理用ドキュメントとしての体裁が整っているものだけが監査証拠として利用できる。**

アジャイル開発では、整った管理文書を作らず、**タスクボード、バックログ、デイリースクラムの記録**といった形で情報が残る（→ [13-1 開発プロセス・手法](../13-software-development-management/13-1-開発プロセス-手法.md)）。**体裁が整っていないという理由で証拠から除外すれば、監査そのものが成立しない**。監査人は開発手法の実態に応じて、何が証拠たりうるかを判断する必要がある。

適切な記述（誤答として並ぶもの）も確認しておく。

| 記述 | 適切な理由 |
| --- | --- |
| 委託先から入手した第三者の保証報告書に依拠できると判断すれば、現地調査を省略できる | 信頼できる第三者の保証は証拠になりうる |
| 本調査の前に、監査対象の実態を把握するための予備調査を実施する | 正しい手順である（→ [2.1 予備調査](#21-予備調査)） |
| 一つの監査目的に対して、通常は複数の監査手続を組み合わせて監査を実施する | 単一の技法では証拠の十分性を確保しにくい |

### 4.2 サンプリング（試査）

すべてを調べる**精査**に対し、一部を抽出して調べることを**試査（サンプリング）**という。

> システム監査における、サンプリング（試査）に関する用語の説明のうち、適切なものはどれか。

答えは、

> **許容逸脱率とは、受け入れることができる所定の内部統制からの逸脱率であり、監査人がサンプルの件数を決めるときに用いられる指標である。**

**許容逸脱率がサンプル件数を決める**という関係が要点である。「10%の逸脱までは許容する」なら少ないサンプルで判断できるが、「1%しか許容しない」なら多くのサンプルを調べなければ結論を出せない。**求める精度が、必要な調査量を決める**。

誤答との区別を押さえる。

| 記述 | 正しくは |
| --- | --- |
| **サンプリングリスク**とは、固有リスクと統制リスクを掛け合わせた結果である | サンプリングリスクは、**抽出した標本が母集団を代表していないために誤った結論を導くリスク**である |
| **統計的サンプリング**とは、特定の種類の例外取引を全て抽出する方法である | 統計的サンプリングは**無作為抽出**に基づく。特定のものを狙って抽出するのは非統計的サンプリング |
| **母集団**とは、評価対象から結論を導き出すのに必要なデータ全体のうち、**リスクが高いデータの集合**である | 母集団は**データ全体**であり、一部ではない |

> **出題** 監査証拠の入手と評価: R4午前I問22 ｜ サンプリング（試査）: H30午前I問21

## 5. 監査文書

| 文書 | 内容 |
| --- | --- |
| 個別監査計画書 | 監査の目的、対象、項目、手続、スケジュールを記す |
| 監査手続書 | 具体的な監査手続を記す |
| 監査チェックリスト | 確認項目の一覧 |
| **監査調書** | **システム監査人が行った監査業務の実施記録であり、監査意見表明の根拠となるべき監査証拠、その他関連資料などをまとめたもの** |
| 監査報告書 | 監査の結論と指摘事項、改善提案を記す |

**監査調書の役割**は、**監査意見の根拠を残す**ことにある。報告書に書いた結論が「なぜそう言えるのか」を、後から検証できるようにしておく。監査人が交代しても、調書があれば判断の過程を追える。

「監査業務の実施記録」「監査意見表明の根拠」という2つのキーワードで、監査報告書や監査手続書と区別できる。

### 5.1 可監査性

> 情報システムの**可監査性**を説明したものはどれか。

答えは、

> **コントロールの有効性を監査できるように、情報システムが設計・運用されていること。**

**監査できるかどうかは、システムの作り方で決まる**という考え方である。たとえば、

- 誰がいつ何を更新したかのログが残っていなければ、統制が機能しているか確認できない
- 処理の途中経過が記録されていなければ、結果が正しいかを追跡できない

こうしたシステムは、どれだけ優秀な監査人が調べても評価しきれない。**監査されることを想定して設計しておく**ことが可監査性であり、これは設計段階で作り込むべき性質である。

誤答との区別を確認する。「監査人が有効な手続を行える能力をもっていること」は監査人側の資質、「監査証拠の十分性と監査報告書の完成度」は監査の品質、「情報システム部門の積極的な協力」は実施環境であり、いずれもシステム側の性質ではない。

> **出題** 監査調書: H21午前I問22 ｜ 可監査性: H30午前I問22

## 6. フォローアップ

監査報告後、改善が実施されているかを確認する活動を**フォローアップ（改善指導）**という。

ここで**監査人の独立性が最も試される**。

> システム監査の改善指導（フォローアップ）において、被監査部門による**改善が計画よりも遅れている**ことが判明したとき、システム監査人が採るべき行動はどれか。

答えは、

> **遅れを取り戻すための方策について、被監査部門の責任者に助言する。**

> システム監査人が行う改善提案のフォローアップとして適切なものは、**改善提案に対する監査対象部門の改善状況をモニタリングする**ことである。

**監査人ができるのは「助言」と「モニタリング」だけ**である。

誤答として並ぶ行動は、すべて**一線を越えている**。

| 行動 | なぜ不適切か |
| --- | --- |
| 具体的な対策の実施を、被監査部門の責任者に**指示する** | 監査人に**指示する権限はない**。改善の責任は被監査部門にある |
| 被監査部門の改善活動に**参加する** | **自分が関与した改善を自分で評価する**ことになり、独立性が失われる |
| 要員の追加を、人事部長に**要求する** | 監査人の権限の範囲外である |
| 改善実施プロジェクトの**管理を行う** | 同上。管理すれば当事者になる |
| 改善提案の内容を示した上で**改善実施計画を策定する** | 計画を立てるのは被監査部門である |

**「助言する・モニタリングする」は可、「指示する・参加する・管理する・計画する」は不可**という線引きを押さえておけば、この種の設問は確実に解ける。[1.2 監査人の責任と独立性](#12-監査人の責任と独立性) で見た「改善の実施責任を負わない」という原則の、具体的な適用である。

> **出題** 改善指導（フォローアップ）: H29午前I問21 ｜ 改善提案のフォローアップ: R3午前I問22

## 7. 監査項目の観点

監査項目は、何を確かめたいかによって分類される。

### 7.1 網羅性

**網羅性**とは、**漏れなく、重複なく記録されていること**である。

> 販売管理システムにおいて、起票された受注伝票が**漏れなく、重複することなく入力されている**ことを確かめる監査手続のうち、適切なものはどれか。

答えは、

> **プルーフリストと受注伝票との照合が行われているか、プルーフリスト又は受注伝票上の照合印を確かめる。**

**プルーフリスト**は、入力されたデータを一覧出力したものである。これと元の伝票を突き合わせれば、入力漏れや二重入力が見つかる。その照合が**実際に行われた証拠（照合印）**を確認するのが監査手続になる。

> 在庫管理システムにおいて、記録された在庫データの**網羅性**のチェックポイントとして適切なものはどれか。

答えは、

> **入庫及び出庫記録に対して、自動的に連番を付与していること。**

**連番を付けておけば、番号の欠落や重複が機械的に検出できる**。これが網羅性を担保する典型的なコントロールである。

誤答はいずれも別の観点を見ている。

| 記述 | 観点 |
| --- | --- |
| 設定された選定基準に従って自動的に購入業者を選定していること | 正当性・準拠性 |
| 適正在庫高であることを責任者が承認していること | 正確性・承認統制 |
| 発注点に達したときに自動的に発注していること | 有効性（業務の効率） |
| **入出庫記録に自動的に連番を付与していること** | **網羅性** |

「漏れなく重複なく」を確かめたいなら、**連番か照合**という発想で選べばよい。

### 7.2 可用性

> マスタファイル管理に関するシステム監査項目のうち、**可用性**に該当するものはどれか。

答えは、

> **マスタファイルが置かれているサーバを二重化し、耐障害性の向上を図っていること。**

**可用性は「使えること」**なので、冗長化や耐障害性がこれにあたる（→ [11-1 情報セキュリティ](../11-security/11-1-情報セキュリティ.md) のCIA）。

誤答の観点も整理する。

| 記述 | 観点 |
| --- | --- |
| **サーバを二重化し、耐障害性の向上を図っている** | **可用性** |
| 複数件まとめて検索・加工するための機能が盛り込まれている | 効率性・有効性 |
| メンテナンスは特権アカウントを付与された者だけに許されている | **機密性** |
| データ入力チェック機能が盛り込まれている | **完全性**（正確性） |

**CIAの3要素で分類する**と機械的に判別できる。

### 7.3 その他の監査項目

**ドキュメント管理**について、稼働しているシステムの仕様とドキュメントの内容が一致しないリスクを低減するコントロールのチェックポイントは、

> **プログラム変更に伴い、ドキュメントを遅滞なく更新すること。**

不一致が起きる原因は「変更したのに文書を直さない」ことなので、**変更と更新を結び付ける**のが直接の対策になる。「ドキュメント一覧を決めておく」「進捗管理を行う」「機密性の対策を講じる」はいずれも別の目的であり、不一致そのものは防げない。この問題は [12-6 保守・廃棄](../12-system-development/12-6-保守-廃棄.md) で見た予防保守の動機とも重なる。

**システム開発計画の策定**におけるコントロールとして適切なのは、

> **不必要なシステム開発コストを抑制するよう、情報システムの目的を達成するための複数の代替案を作成し、比較検討する。**

誤答は、「全体最適より業務上の利便性を優先する」（全体最適を損なう）、「開発作業に着手してから承認を得る」（承認は着手前）、「利用部門とシステム部門の役割分担を決めずに実行する」（責任が不明確になる）と、いずれも統制を弱める内容になっている。

**クラウドサービスの導入検討**における、情報の消失の予防に関するチェックポイントは、

> **クラウドサービスを提供する事業者に信頼が置け、かつ、事業やサービスが継続して提供されるかどうかが検討されているか。**

クラウドでは**事業者が撤退・破綻すれば預けた情報が失われうる**。これは自社内のシステムにはないリスクで、技術的な対策では防げない。だから**事業者の継続性そのものを評価する**ことが、消失予防の中心になる。ID一元管理（利便性）、最大許容停止時間（可用性）、施設内の暗号化（機密性）はいずれも別の観点である。

> **出題** 網羅性の監査手続: H25午前I問21、H27午前I問22 ｜ 網羅性のチェックポイント: H26午前I問22、H29午前I問22 ｜ ドキュメント管理のコントロール: H23午前I問22 ｜ システム開発計画のコントロール: H25午前I問22 ｜ クラウドサービスの監査: R1午前I問21 ｜ 可用性に関する監査項目: R3午前I問21

## 8. 関連する基準

| 基準 | 内容 |
| --- | --- |
| **システム監査基準** | **監査人の行為規範**。どう監査すべきかを定める |
| **システム管理基準** | **監査の判断尺度**。情報システムがどう管理されるべきかを定める |

> **「システム管理基準」の説明**はどれか。

答えは、

> **情報戦略を立案し、効果的な情報システム投資とリスクを低減するためのコントロールを適切に整備・運用するための事項をとりまとめたもの。**

**システム監査基準が「監査人のための基準」、システム管理基準が「監査される側のあるべき姿」**という対になっている。監査人は後者に照らして前者の手順で評価する、という関係である。

誤答に並ぶのは、いずれも別のガイドラインである。「コンピュータウイルス対策基準」「コンピュータ不正アクセス対策基準」「ソフトウェア管理ガイドライン」に相当する内容が挙げられている。

システム管理基準は、情報戦略の策定における留意事項も定めており、その観点は [17-1 情報システム戦略](../17-system-strategy/17-1-情報システム戦略.md) で扱う。

> **出題** システム管理基準: H22午前I問22

## この章のまとめ

- システム監査が点検・評価するのは**ガバナンス、マネジメント、コントロール**の3つ。
- **監査人の責任は「監査意見」まで**。改善の実施責任は負わない。これが独立性を支える。
- **予備調査は実態を知る段階、本調査は証拠を集める段階**。「監査手続」は証拠を入手するための手順を指す。
- **ウォークスルー法はデータの流れを最初から最後まで追ってコントロールを確認する**。
- 技法に関する設問では、**「〜しなければならない」という過度な制約の選択肢を疑う**。チェックリストを作るのは監査人である。
- **許容逸脱率がサンプル件数を決める**。母集団はデータ全体であり、一部ではない。
- **監査調書は監査意見の根拠を残す記録**。**可監査性は、監査できるようにシステムが設計・運用されていること**。
- フォローアップで監査人ができるのは**助言とモニタリングだけ**。指示・参加・管理・計画はいずれも独立性を損なう。
- 監査項目は観点で分類する。**網羅性なら連番や照合、可用性なら冗長化、機密性ならアクセス制限、完全性なら入力チェック**。
- **システム監査基準は監査人の行為規範、システム管理基準は監査の判断尺度**。
