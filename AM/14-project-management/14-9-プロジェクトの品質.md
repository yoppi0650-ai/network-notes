# 14-9 プロジェクトの品質

成果物とプロセスの**品質を計画し、保証し、管理する**領域を扱う。

品質マネジメントの出発点は、**品質は検査で作り込むものではない**という認識である。完成してから検査して不良を弾くのでは、作り直しの費用がかかるうえ、すべての不良を見つけられる保証もない。**作る過程で品質を確保する**という発想が、品質保証と品質管理を分ける考え方の根底にある。

午前Iの問19前後から出題される。16年で1問。

## 1. 品質マネジメントの3つの活動

| 活動 | 内容 | 対象 |
| --- | --- | --- |
| **品質マネジメント計画** | 品質の目標と、それを達成する方法を定める | 計画 |
| **品質保証（QA）** | **プロセス**が適切かを確認し、改善する | **やり方** |
| **品質管理（QC）** | **成果物**が基準を満たすかを検査する | **できたもの** |

**品質保証はプロセス、品質管理は成果物**という区別が基本になる。

この分離に意味があるのは、**成果物の品質はプロセスの品質に従う**からである。レビューを飛ばし、テストを省いたプロセスからは、検査をいくら厳しくしても良い成果物は出てこない。品質保証が「やり方が守られているか」を見るのは、結果を予防的に管理するためである。

## 2. 品質の定量的評価

品質は感覚ではなく**数値（メトリクス）**で評価する。測れなければ改善もできない。

> **品質の定量的評価の指標**のうち、**ソフトウェアの保守性**の評価指標になるものはどれか。

答えは、

> **（修正時間の合計）÷（修正件数）**

これは**1件あたりの平均修正時間**を表す。保守性とは「**修正しやすさ**」なので（→ [12-1 システム・ソフトウェア要件定義](../12-system-development/12-1-システム-ソフトウェア-要件定義.md)）、1件直すのにどれだけ時間がかかるかが直接の指標になる。この値が小さいほど保守しやすいソフトウェアである。

誤答として並ぶ指標が、それぞれどの品質特性に対応するかを整理する。

| 指標 | 評価しているもの |
| --- | --- |
| （最終成果物に含まれる誤りの件数）÷（最終成果物の量） | **誤り密度**。**信頼性**の指標 |
| **（修正時間の合計）÷（修正件数）** | **平均修正時間**。**保守性**の指標 |
| （変更が必要となるソースコードの行数）÷（移植するソースコードの行数） | **移植性**の指標 |
| （利用者からの改良要求件数）÷（出荷後の経過月数） | 改良要求の発生頻度。品質特性というより利用状況の指標 |

**分母と分子が何かを読めば、何を測っているかが分かる**。「修正」に関する指標なら保守性、「誤り」なら信頼性、「変更が必要な行数の割合」なら移植性である。

品質特性の分類そのものは [12-1 システム・ソフトウェア要件定義](../12-system-development/12-1-システム-ソフトウェア-要件定義.md) で扱う。

## 3. 品質を作り込む活動

### 3.1 レビューとテスト

| 活動 | タイミング | 参照 |
| --- | --- | --- |
| **レビュー** | 設計・実装の**途中** | [12-2 設計](../12-system-development/12-2-設計.md) |
| **テスト** | 作ったあと | [12-4 統合・テスト](../12-system-development/12-4-統合-テスト.md) |

**誤りを早く見つけるほど修正コストは小さい**という原則がここでも効く。要件定義の誤りを要件定義中に見つければ文書の修正で済むが、稼働後に見つかれば設計・実装・テストをやり直すことになる。レビューに工数を割くのは、この差を見越した投資である。

### 3.2 品質管理の図法

品質データの分析には、**QC七つ道具**と呼ばれる図法が使われる。

| 図法 | 用途 |
| --- | --- |
| パレート図 | 件数の多い順に並べ、累積比率を示す。重点管理する対象を選ぶ |
| 特性要因図（魚の骨図） | 結果に影響する要因を系統的に整理する |
| 管理図 | 時系列の変動を見て、異常を検出する |
| ヒストグラム | 分布の形を見る |
| 散布図 | 2つの変量の関係を見る（→ [1-2 応用数学](../01-basic-theory/1-2-応用数学.md) の相関係数） |

これらの詳細は [22-2 業務分析・データ利活用](../22-corporate-activities/22-2-業務分析-データ利活用.md) で扱う。

### 3.3 信頼度成長モデル

テストで発見される累積バグ数の推移から、**品質が安定したかを判断する**手法がある。ゴンペルツ曲線などの信頼度成長モデルがこれにあたる（→ [12-4 統合・テスト](../12-system-development/12-4-統合-テスト.md)）。

プロジェクトマネジメントの観点では、これが**「テストを終えてよいか」の判断根拠**になる点が重要である。「予定した期間が来たから終わり」ではなく、**データに基づいて品質を判断する**ための道具である。

## この章のまとめ

- **品質保証はプロセス（やり方）、品質管理は成果物（できたもの）**を対象とする。成果物の品質はプロセスの品質に従うので、予防的にプロセスを見る。
- 定量的評価の指標は**分母と分子で何を測っているかが分かる**。**保守性は（修正時間の合計）÷（修正件数）**、信頼性は誤り密度、移植性は変更が必要な行数の割合。
- **誤りを早く見つけるほど修正コストは小さい**。レビューはそのための投資である。
