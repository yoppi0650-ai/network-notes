# 14-1 プロジェクトマネジメント

プロジェクトを成功させるための管理の枠組みを扱う。分野14の入口として、**プロジェクトとは何か**、**誰がどう関わるか**、**どういう手順で進めるか**を整理する。

プロジェクトマネジメントが独立した技術体系になっているのは、プロジェクトが**有期で一回限り**だからである。定常業務なら前回のやり方を繰り返せばよいが、プロジェクトは毎回違う。だからこそ、個別の内容に依存しない**共通の進め方**を体系化する意味がある。

午前Iの問18前後から出題される。16年で2問。個別の管理領域（スコープ、時間、コストなど）は 14-2 以降で扱う。

## 1. プロジェクトの定義

**プロジェクト**とは、**独自の成果物やサービスを創出するための、有期性のある活動**である。2つの特徴が本質になる。

| 特徴 | 意味 |
| --- | --- |
| **有期性** | 明確な始まりと終わりがある |
| **独自性** | 過去とまったく同じものではない |

この2つから、プロジェクトマネジメントの難しさが導かれる。終わりがあるので**期限内に終えなければならず**、独自なので**前例がなく見積りが難しい**。定常業務のように経験則だけで回せないので、計画・監視・制御を意識的に行う必要が生じる。

## 2. 標準とフレームワーク

| 標準 | 概要 |
| --- | --- |
| **PMBOK ガイド** | 米国PMIが策定。プロジェクトマネジメントの知識体系。版によって構成が変わる |
| **JIS Q 21500**（ISO 21500） | プロジェクトマネジメントの手引。国際規格 |
| P2M | 日本発。プログラムマネジメントまで含む |

いずれも**「こうすれば必ず成功する」という手順書ではなく、考慮すべき事柄のカタログ**である。[13-1 開発プロセス・手法](../13-software-development-management/13-1-開発プロセス-手法.md) の共通フレームと同じく、プロジェクトの特性に合わせて取捨選択（テーラリング）して使う。

## 3. プロセス群

JIS Q 21500 では、プロジェクトマネジメントのプロセスを5つの**プロセス群**に分類する。

| プロセス群 | 内容 | 属するプロセスの例 |
| --- | --- | --- |
| **立上げ** | プロジェクトを正式に認可し、開始する | **プロジェクト憲章の作成**、ステークホルダの特定 |
| **計画** | 目標と達成方法を定める | **スコープの定義**、WBSの作成、スケジュールの作成、予算の作成 |
| **実行** | 計画に従って作業を行う | **品質保証の遂行**、**プロジェクトチームの編成**、情報の配布 |
| **管理** | 進捗を監視し、必要なら是正する | 変更の管理、スコープの管理、スケジュールの管理 |
| **終結** | プロジェクトやフェーズを正式に完了させる | 教訓の収集、プロジェクトフェーズの終結 |

> JIS Q 21500:2018 によれば、プロジェクトマネジメントのプロセスのうち、**計画のプロセス群に属するプロセス**はどれか。

答えは **スコープの定義**である。

判別のコツは、**「何をするかを決める」のが計画、「実際に手を動かす」のが実行**という区別である。

| プロセス | 属する群 | 理由 |
| --- | --- | --- |
| **スコープの定義** | **計画** | 何を作るかを**決める** |
| 品質保証の遂行 | 実行 | 実際に品質保証活動を**行う** |
| プロジェクト憲章の作成 | **立上げ** | プロジェクトを**認可する**文書であり、計画の前にある |
| プロジェクトチームの編成 | 実行 | 実際に人を**集める** |

**プロジェクト憲章が「立上げ」に属する**のが見落としやすい点である。憲章は計画を立てるための前提（なぜやるのか、誰が責任者か）を定めるもので、計画そのものではない（→ [14-2 プロジェクトの統合](14-2-プロジェクトの統合.md)）。

なお、これらのプロセス群は**順番に1回ずつ実行するものではない**。計画と実行と管理は繰り返し行き来する。ウォータフォールの工程とは別の概念である。

> **出題** JIS Q 21500のプロセス群: R3午前I問18

## 4. 関係者の役割

### 4.1 4つのマネジャーとPMO

> PMBOK ガイド第6版によれば、プロジェクト・マネジャー、プログラム・マネジャー、ポートフォリオ・マネジャー、プロジェクトマネジメント・オフィス（PMO）は、それぞれ他と異なる役割を担っている。**PMOの役割**はどれか。

答えは、

> **プロジェクトに関連するガバナンス・プロセスを標準化し、資源、方法論、ツール及び技法の共有を促進する。**

4者の役割を、**扱う範囲**で整理する。

| 役割 | 扱う範囲 | 仕事 |
| --- | --- | --- |
| **プロジェクト・マネジャー** | **1つのプロジェクト** | **プロジェクトの要求事項を満たすために、知識、スキル、ツールと技法をプロジェクトのアクティビティへ適用する** |
| **プログラム・マネジャー** | **関連する複数のプロジェクト** | **戦略目標に整合させるよう、関連する複数のプロジェクトに影響する制約条件及びコンフリクトを解消する** |
| **ポートフォリオ・マネジャー** | **組織全体の投資** | **戦略目標を達成するために、プログラム及びプロジェクトの最適な組合せを選択して、構成要素の優先順位を決定し、必要な資源を提供する** |
| **PMO** | **組織の仕組み** | **ガバナンス・プロセスを標準化し、資源・方法論・ツール・技法の共有を促進する** |

**PMOだけが「個別のプロジェクトを動かす」のではなく「組織の仕組みを整える」立場**にある点が決め手になる。標準化、テンプレートの提供、研修、ツールの整備などを通じて、**どのプロジェクトも一定の水準で進められるようにする**のがPMOの役割である。

残る3者は扱う粒度で区別できる。**プロジェクト（1件）→ プログラム（関連する複数）→ ポートフォリオ（組織全体の選択と優先順位）**という階層になっている。

### 4.2 ステークホルダ

プロジェクトに利害関係をもつ人や組織を**ステークホルダ**という。発注者、利用者、開発チーム、経営層、取引先、規制当局などが含まれる。

ステークホルダの特定と関与の管理は [14-3 プロジェクトのステークホルダ](14-3-プロジェクトのステークホルダ.md) で扱う。

> **出題** PMOの役割: R1午前I問18

## この章のまとめ

- プロジェクトの特徴は**有期性と独自性**。前例がないからこそ、計画・監視・制御を意識的に行う必要がある。
- PMBOKやJIS Q 21500は**手順書ではなくカタログ**。テーラリングして使う。
- プロセス群は**立上げ・計画・実行・管理・終結**。**「決める」のが計画、「手を動かす」のが実行**。**プロジェクト憲章の作成は立上げ**に属する。
- 役割は扱う範囲で区別する。**プロジェクト（1件）→ プログラム（関連する複数）→ ポートフォリオ（組織全体）**。**PMOだけが個別のプロジェクトではなく組織の仕組みを扱う**。
