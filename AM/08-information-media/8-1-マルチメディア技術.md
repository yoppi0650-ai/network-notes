# 8-1 マルチメディア技術

画像・音声・動画をコンピュータで扱うための技術を扱う。

この分野を貫く問題は**データ量**である。生の画像や音声は膨大なデータになるため、そのままでは保存も伝送もできない。どう表現し（画像形式）、どう小さくし（圧縮符号化）、どう描くか（コンピュータグラフィックス）──いずれもこの制約への対処として理解できる。

午前Iの問8〜10前後から出題される。16年で9問。**コンピュータグラフィックスの要素技術**が繰り返し問われる。

## 1. 画像の表現

### 1.1 ラスタ形式とベクタ形式

| 形式 | 表現方法 | 特徴 |
| --- | --- | --- |
| **ラスタ（ビットマップ）形式** | 画素（ピクセル）の集まりとして色を記録する | 写真に向く。**拡大するとギザギザになる** |
| **ベクタ形式** | 図形を数式（座標・線・曲線）として記録する | 図形に向く。**任意の倍率に拡大しても劣化しない** |

ラスタ形式の例はJPEG、PNG、GIF、BMP、TIFF。ベクタ形式の例はSVG、EPSである。

### 1.2 フォント

同じ区別がフォントにも当てはまる。

| 種類 | 表現方法 |
| --- | --- |
| ビットマップフォント | 文字を画素の集まりとして持つ |
| **アウトラインフォント** | 文字の輪郭を**数式（曲線）**として持つ |

> **ビットマップフォントよりもアウトラインフォントの利用が適している場合**はどれか。

答えは、

> **文字を任意の倍率に拡大して表示する。**

アウトラインフォントは輪郭を数式で持つので、**どんな倍率でも滑らかに描ける**。ビットマップフォントは特定のサイズ用の画素パターンなので、拡大するとギザギザになる。

誤答との区別も押さえる。

| 記述 | 正しくは |
| --- | --- |
| 英数字だけでなく、漢字も表示する | 文字種はフォント形式とは無関係 |
| 各文字の幅を一定にして表示する | 等幅かプロポーショナルかは別の属性 |
| 画面上にできるだけ**高速に**表示する | **ビットマップフォントのほうが速い**。アウトラインは表示のたびに輪郭から画素を計算（ラスタライズ）する必要がある |

**アウトラインは「拡大に強い」代わりに「描画が重い」**という関係にある。ビットマップフォントが小さな組込み機器で今も使われるのは、計算資源が限られるためである。

### 1.3 データ量の計算

ラスタ画像のデータ量は、

$$ \text{データ量} = (\text{横の画素数}) \times (\text{縦の画素数}) \times (1画素あたりのビット数) $$

で求まる。計算の手順と注意点は [3-5 入出力装置](../03-computer-components/3-5-入出力装置.md) で扱う。音声のデータ量は [1-4 通信に関する理論](../01-basic-theory/1-4-通信に関する理論.md) の標本化・量子化から求まる。

> **出題** アウトラインフォント: R6午前I問8

## 2. 圧縮と符号化

### 2.1 可逆圧縮と非可逆圧縮

| 分類 | 特徴 | 例 |
| --- | --- | --- |
| **可逆圧縮** | 完全に元に戻せる | ZIP、PNG、GIF、ハフマン符号（→ [1-3 情報に関する理論](../01-basic-theory/1-3-情報に関する理論.md)） |
| **非可逆圧縮** | 元に戻せないが、圧縮率が高い | JPEG、MP3、MPEG、H.264 |

**非可逆圧縮が成立するのは、人間の知覚が鈍い部分を捨てられるから**である。画像では色の微妙な変化より輝度の変化に敏感、音声では大きな音の直後の小さな音が聞こえない（マスキング）といった性質がある。これらを利用して「捨てても気づかれにくい情報」から削ることで、可逆圧縮では到達できない圧縮率を得る。

文書やプログラムは1ビットでも変われば意味が壊れるので可逆圧縮しか使えない。**対象によって許される圧縮が違う**のが、この区別の実務的な意味である。

### 2.2 主な符号化方式

| 方式 | 対象 | 用途 |
| --- | --- | --- |
| JPEG | 静止画 | 写真 |
| GIF / PNG | 静止画 | 図、イラスト |
| MPEG-1 | 動画 | Video CD |
| MPEG-2 | 動画 | DVD、地上デジタル放送 |
| **H.264/AVC**（MPEG-4 AVC） | 動画 | **ディジタルハイビジョン対応のビデオカメラ、ワンセグ**、Blu-ray |
| H.265/HEVC | 動画 | 4K・8K放送 |
| MP3 / AAC | 音声 | 音楽配信 |
| **G.729** | 音声 | **VoIP**（→ [10-5 ネットワーク応用](../10-network/10-5-ネットワーク応用.md)） |
| AC-3 | 音声 | 映画の多チャンネル音声 |

> **ディジタルハイビジョン対応のビデオカメラやワンセグの映像圧縮符号化方式**として採用されているものは **H.264/AVC** である。

誤答の区別も押さえる。**AC-3とG.729は音声**の符号化方式であり映像ではない。**MPEG-1は古い規格**で、Video CD程度の画質しかなくハイビジョンには使われない。

> **出題** H.264/AVC: H27午前I問9

## 3. マルチメディア記述言語

| 言語 | 用途 |
| --- | --- |
| **SVG** (Scalable Vector Graphics) | **W3Cで仕様が定義され、矩形や円、直線、文字列などの図形オブジェクトをXML形式で記述し、Webページでの図形描画にも使うことができる画像フォーマット** |
| **SMIL** (Synchronized Multimedia Integration Language) | **動画や音声などのマルチメディアコンテンツのレイアウトや再生のタイミングをXMLフォーマットで記述するためのW3C勧告** |
| MathML | 数式をXML形式で記述する（→ [12-2 設計](../12-system-development/12-2-設計.md)） |

**SVGとSMILはどちらもXMLベースのW3C勧告**だが、扱う対象が違う。**SVGは「図形」、SMILは「レイアウトとタイミング」**である。

SVGがベクタ形式であることの利点は [1.1](#11-ラスタ形式とベクタ形式) のとおりで、拡大しても劣化せず、テキストなので検索も編集もできる。また、スクリプトで動的に書き換えられるため、Webページ上のグラフや図の描画に広く使われている。

誤答として並ぶものとの区別も確認する。

| 記述 | 実際は何か |
| --- | --- |
| OpenGL | 3次元グラフィックスの描画API。画像フォーマットではない |
| PNG、TIFF | **ラスタ形式**の画像フォーマット |
| Ajax | 非同期通信の技術（→ [10-5 ネットワーク応用](../10-network/10-5-ネットワーク応用.md)） |
| CSS | Webページの見栄えを指定するスタイルシート |

> **出題** SVG: R3午前I問8、R7午前I問8 ｜ SMIL: H28午前I問8

## 4. コンピュータグラフィックス

**要素技術の名前と説明の対応**が繰り返し問われる。それぞれ「何をする技術か」を一語で押さえる。

| 技術 | 内容 |
| --- | --- |
| **アンチエイリアシング** | **周辺の画素との平均化演算などを施すことで、斜め線や曲線のギザギザを目立たなくする** |
| **テクスチャマッピング** | **形状が定義された物体の表面に、別に定義された模様を張り付けて画像を作成する** |
| **メタボール** | **物体を球やだ円体の集合として疑似的にモデル化する** |
| **レイトレーシング法** | **光源からの光線の経路を計算することで光の反射や透過などを表現し、物体の形状を描画する**。すべてのピクセルについて視線と物体との交点を計算し、最も近い交点を選ぶことで隠面消去も行う |
| **ラジオシティ法** | **拡散反射面間の相互反射による効果を考慮して、拡散反射面の輝度を決める** |
| Zバッファ法 | 各画素の奥行きを記録して隠面消去を行う |
| シェーディング | 面の明暗を計算して立体感を出す |

### 4.1 判別のポイント

設問では**これらの説明が互いに入れ替えられる**。キーワードで紐付けるのが確実である。

| キーワード | 技術 |
| --- | --- |
| **ギザギザを目立たなくする** | アンチエイリアシング |
| **模様を張り付ける** | テクスチャマッピング |
| **球やだ円体の集合** | メタボール |
| **光線を追跡する** | レイトレーシング法 |
| **相互反射** | ラジオシティ法 |

### 4.2 レイトレーシングとラジオシティ

この2つは「光の扱い方」で対になっている。

- **レイトレーシング法**は、**視点から光線を逆にたどる**。鏡面反射や透過（ガラスや水）の表現に強い。金属やガラスの質感が得意である。
- **ラジオシティ法**は、**面と面の間で光がやり取りされる**様子を計算する。壁で反射した光が隣の壁をうっすら照らす、といった**間接光（相互反射）**の表現に強い。室内の自然な明るさが得意である。

両者は得意分野が補完的なので、実際のレンダリングでは組み合わせて使われる。「**視線の追跡がレイトレーシング、面どうしの反射がラジオシティ**」と対にして覚えるとよい。

なお、設問の誤答では「メタボールは、反射・透過方向への視線追跡を行わず、与えられた空間中のデータから輝度を計算する」といった、**別技術（ボリュームレンダリング）の説明がメタボールに充てられる**こともある。メタボールは**モデリング（形を作る）技術**であって、**レンダリング（描画する）技術ではない**という区別で判断できる。

> **出題** コンピュータグラフィックスの要素技術: H21午前I問10、H22午前I問10、R5午前I問8

## 5. バーチャルリアリティ

**バーチャルリアリティ（VR）**では、仮想世界を作る**モデリング**と、それを表示する**レンダリング**が区別される。

> バーチャルリアリティにおけるモデリングに関する記述のうち、**レンダリング**の説明はどれか。

答えは、

> **仮想世界の情報をディスプレイに描画可能な形式の画像に変換する処理。**

**レンダリングは「データ → 画像」の変換**である。3次元の座標やマテリアルの情報を、2次元の画素の集まりに落とし込む。

誤答として並ぶ記述は、VRを構成する**別の処理**である。

| 記述 | 処理の名前 |
| --- | --- |
| ウェアラブルカメラ、慣性センサなどを用いて**非言語情報を認識**する処理 | センシング／認識 |
| 視覚的に現実世界と仮想世界を融合させるために、それぞれの3次元座標を**一致させる**処理 | **レジストレーション**（AR で重要） |
| 時間経過とともに生じる物の移動などの変化を、モデル化したものを**物理法則に当てはめて変化させる**処理 | **シミュレーション** |

関連用語も整理しておく。

| 用語 | 内容 |
| --- | --- |
| VR（仮想現実） | 完全に仮想の世界に没入する |
| AR（拡張現実） | 現実世界に仮想の情報を重ねる |
| MR（複合現実） | 現実と仮想を融合し、相互に作用させる |

**ARで座標の一致（レジストレーション）が重要になる**のは、現実の物体の上にぴったり重ねなければ違和感が生じるからである。VRでは現実と合わせる必要がないので、この処理は要らない。

> **出題** レンダリング: H30午前I問8

## この章のまとめ

- **ラスタは画素の集まり、ベクタは数式**。**アウトラインフォントは任意の倍率に拡大しても劣化しない**が、描画は重い。
- **非可逆圧縮が成立するのは、人間の知覚が鈍い部分を捨てられるから**。文書やプログラムには使えない。
- **H.264/AVCはハイビジョンのビデオカメラやワンセグの映像符号化方式**。AC-3とG.729は音声である。
- **SVGは図形をXMLで記述する画像フォーマット、SMILはレイアウトと再生タイミングをXMLで記述する**。
- CGの要素技術はキーワードで紐付ける。**ギザギザ＝アンチエイリアシング、模様＝テクスチャマッピング、球の集合＝メタボール、光線追跡＝レイトレーシング、相互反射＝ラジオシティ**。
- **レンダリングは「仮想世界の情報を描画可能な画像に変換する処理」**。座標の一致はレジストレーション、物理法則による変化はシミュレーション。
