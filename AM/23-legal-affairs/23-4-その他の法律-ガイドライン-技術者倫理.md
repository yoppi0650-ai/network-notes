# 23-4 その他の法律・ガイドライン・技術者倫理

**標準化**、**環境・社会に関するガイドライン**、そして**技術者としての倫理**を扱う。

ここに集まるのは、法律のように罰則で強制されるわけではないが、**従わなければ事実上ビジネスが成り立たない**ルールである。国際標準に適合しなければ製品が売れず、環境表示の約束を破れば信用を失う。技術者倫理に至っては、守らせる仕組みすらないが、守らなければ職業として成立しない。

午前Iの問25〜問27あたりから出題される。16年で2問。出題数は少ないが、**標準化は [10-1 ネットワーク方式](../10-network/10-1-ネットワーク方式.md) 以降で扱うプロトコルがなぜ相互接続できるのかという根本に関わる**ため、ネットワークスペシャリストとして理解しておく価値が大きい。

## 1. 標準化の仕組み

### 1.1 標準が生まれる三つの道筋

**異なるメーカの機器どうしが通信できるのはなぜか**。答えは、共通のルールが文書として定められ、各社がそれに従って実装しているからである。その共通ルールが**標準（規格）**である。

標準には、できかたによって三つの型がある。

| 種類 | 成立の仕方 | 例 |
| --- | --- | --- |
| **デジュール標準**（公的標準） | **標準化機関が所定の手続きを経て制定**する | ISO、IEC、ITU-T、JIS |
| **デファクトスタンダード**（事実上の標準） | **市場で広く使われた結果**、標準として扱われる | かつてのPC/AT互換機、PDF（後にISO化） |
| **フォーラム標準** | **関心をもつ企業・団体が集まって**策定する | IETFのRFC、W3C、Wi-Fi Alliance、USB-IF |

**この三つは排他的ではなく、移り変わる**。フォーラム標準として始まったものが市場で広まってデファクトになり、やがて公的機関に取り込まれてデジュール標準になる、という経路をたどることが多い。TCP/IPがまさにこの例で、IETFのRFCというフォーラム標準から出発し、事実上の標準となった。

**デジュール標準が時間をかけて合意を形成するのに対し、フォーラム標準は速い**。インターネット関連技術の進化が速かったのは、RFCという軽い手続きで標準を出せたことが大きい。一方で、公的標準には**政府調達で参照される**という強みがある（→ [2章](#2-国際標準に適合する利点)）。

### 1.2 主な標準化機関

| 機関 | 対象分野 |
| --- | --- |
| **ISO**（国際標準化機構） | 工業製品・サービス全般。品質マネジメント（ISO 9001）、環境マネジメント（ISO 14001）、情報セキュリティ（ISO/IEC 27001） |
| **IEC**（国際電気標準会議） | 電気・電子技術 |
| **ISO/IEC JTC 1** | **ISOとIECの合同技術委員会**。情報技術分野を担当 |
| **ITU-T**（国際電気通信連合 電気通信標準化部門） | 電気通信。**勧告**という形で発行（Vシリーズ、Gシリーズなど） |
| **IEEE**（米国電気電子学会） | **IEEE 802シリーズ**（LAN/MAN）など |
| **IETF** | インターネット技術。**RFC** |
| **W3C** | Web技術（HTML、CSS、XML） |
| **JIS**（日本産業規格） | 日本国内の産業標準 |

ネットワーク分野では、**物理層・データリンク層はIEEE、ネットワーク層より上はIETF、通信事業者網はITU-T**というおおまかな分担がある。この分担を知っていると、規格番号を見ただけでどの層の話かの見当がつく。

## 2. 国際標準に適合する利点

> **ISO、IEC、ITU などの国際標準に適合した製品**を製造及び販売する**利点**として適切なものはどれか。

答えは、

> **WTO政府調達協定の加盟国では、政府調達は国際標準の仕様に従って行われる。**

WTO（世界貿易機関）の**政府調達に関する協定**は、加盟国に対し、政府調達の技術仕様を**国際規格に基づいて定める**ことを求めている。各国が独自の規格で調達要件を作ると、それが事実上の貿易障壁になってしまうからである。

したがって、**国際標準に適合していれば、加盟国の政府調達市場に参入する道が開ける**。これが、公的標準に準拠することの最も具体的な見返りになる。

誤答はいずれも「言い過ぎ」である。

| 記述 | なぜ誤りか |
| --- | --- |
| 国際標準に適合しない競合製品に比べて、**技術的に優位であることが保証される** | 標準は**相互接続性や最低限の品質を確保する**ものであって、**優位性を保証するものではない**。むしろ標準準拠品は機能が横並びになりやすい |
| 国際標準に適合するために必要な特許は、**全て無償でライセンスを受けられる** | **誤り**。標準必須特許は、**RANDまたはFRAND条件**（公正・合理的かつ非差別的）でライセンスされるのが原則で、**無償とは限らない** |
| 輸出先国の**国内標準及び国内法規の規制を受けることなく**製品を輸出できる | **誤り**。国際標準への適合は、**各国の法規制を免除するものではない**。電波法の技適のように、国ごとの認証が別途必要になる |

**標準必須特許とFRAND条件**は、ネットワーク技術を学ぶうえでも知っておきたい。ある規格を実装すると必然的に侵害してしまう特許を**標準必須特許（SEP）**という。これを権利者が自由に差し止められると標準が機能しないので、標準化機関は参加者に対し、**FRAND条件でライセンスする意思の表明**を求める。無償ではないが、不当に高額だったり特定の企業だけ拒否したりはできない、という均衡点である。

> **出題** 国際標準への適合: H29午前I問27

## 4. 環境に関する法規とガイドライン

### 4.1 環境表示

> 環境省の**環境表示ガイドライン**によれば、**環境表示**の説明はどれか。

答えは、

> **製品やサービスについて、環境に配慮した点や環境負荷の低減効果などの特徴、事業者の環境配慮への姿勢を、説明文やシンボルマーク、図表などを通して主張したもの。**

**環境表示とは、要するに「環境についての主張」**である。「この製品はリサイクル材を使っています」という文章も、エコマークのようなシンボルも、すべて環境表示にあたる。

ガイドラインが整備されているのは、**根拠のない環境主張（グリーンウォッシュ）を防ぐ**ためである。環境配慮は消費者の購買判断に影響するため、曖昧な表現や検証できない主張が横行すると市場が機能しなくなる。そこで、**正確であること、検証可能であること、意味が明確であること**などが求められる。

誤答の三つは、それぞれ**別の環境関連の仕組み**の説明になっている。混同しやすいので整理しておく。

| 誤答の説明 | 実際には何か |
| --- | --- |
| 企業や国が排出枠を決め、不足分と超過分を市場で取引する | **排出量取引**（キャップ・アンド・トレード） |
| 公的機関が率先して環境物品の調達を推進し、需要の転換を促進するために必要な事項を規定したもの | **グリーン購入法**（国等による環境物品等の調達の推進等に関する法律） |
| 再生可能エネルギーによる電力の環境付加価値を取引可能な証書にしたもの | **グリーン電力証書** |

**四つを分ける軸は「何を扱う仕組みか」**である。環境表示は**情報**（主張の仕方）、排出量取引は**排出枠**、グリーン購入法は**調達**、グリーン電力証書は**環境付加価値**を扱う。この対応を押さえれば選び分けられる。

> **出題** 環境表示ガイドライン: H27午前I問25

### 4.2 その他の環境関連法規

| 法規・制度 | 内容 |
| --- | --- |
| **グリーン購入法** | 国等の機関に**環境物品等の調達の推進**を義務づける。調達方針の策定・公表 |
| **資源有効利用促進法** | 3R（Reduce・Reuse・Recycle）の推進。**パソコンや小型二次電池の回収・再資源化** |
| **小型家電リサイクル法** | 使用済小型電子機器等の回収・再資源化 |
| **省エネ法**（エネルギーの使用の合理化等に関する法律） | エネルギー使用量の報告、**トップランナー制度**（最も優れた機器の水準を目標値にする） |
| **RoHS指令**（EU） | 電子機器における**特定有害物質の使用制限**（鉛、水銀、カドミウムなど） |
| **WEEE指令**（EU） | 電気・電子機器廃棄物の回収・リサイクルを製造者に義務づける |
| **エコマーク** | 環境保全に資する商品を認定する日本の制度（**第三者認証型の環境ラベル**） |

**環境ラベルには三つの型**がある。この分類はISO 14020シリーズで定められている。

| 型 | 内容 | 例 |
| --- | --- | --- |
| **タイプI** | **第三者機関が基準を定めて認証**する | エコマーク |
| **タイプII** | **事業者自身による自己宣言**。第三者認証はない | 自社製品への「省エネ設計」表示 |
| **タイプIII** | **環境負荷のデータを定量的に開示**する。良し悪しの判定はしない | エコリーフ環境ラベル |

**タイプIIIが「判定しない」**のが特徴的である。ライフサイクルアセスメント（LCA）に基づく数値を示すだけで、環境によいかどうかは利用者が判断する。これは、製品の性格によって何が「よい」かが変わるためで、**判定を押し付けずに情報を提供する**という考え方に立っている。

データセンタやネットワーク機器の消費電力が問題になる文脈では、[4-2 システムの評価指標](../04-system-components/4-2-システムの評価指標.md) で扱った **PUE**（Power Usage Effectiveness）のような指標も、広い意味で環境配慮の評価に使われる。

## 5. 技術者倫理

### 5.1 なぜ倫理が必要か

技術者の判断は、**本人以外には正しさを検証しにくい**。暗号の実装に弱点があっても、設計書に書かれていない手抜きがあっても、専門知識のない発注者や利用者には分からない。この**情報の非対称性**こそが、技術者に倫理を求める理由である。

法律が禁じていないことでも、専門家として許されないことがある。たとえば、脆弱性を認識しながら「指摘されていないから」と放置することは、違法とは限らないが倫理的には問題がある。

### 5.2 情報倫理と専門職としての責務

主要な行動規範に共通して現れる原則を挙げる。

| 原則 | 内容 |
| --- | --- |
| **公衆の安全・健康・福祉の優先** | 依頼者や自社の利益よりも、**公衆の利益を優先する** |
| **誠実性** | 虚偽の報告をしない。能力を偽らない |
| **専門能力の維持** | 継続的に学習し、**能力の範囲内で業務を引き受ける** |
| **守秘義務** | 業務上知り得た情報を漏らさない |
| **利益相反の回避** | 判断が歪む立場に身を置かない。やむを得ない場合は開示する |

**「能力の範囲内で業務を引き受ける」**は見落とされやすい。できないことをできると言って受注すること自体が倫理違反になる。これは [14-5 プロジェクトの資源](../14-project-management/14-5-プロジェクトの資源.md) や [16-1 システム監査](../16-system-audit/16-1-システム監査.md) で見た「監査人の独立性と専門能力」という要請と同じ根をもつ。

### 5.3 公益通報者保護法

技術者が組織内の不正を知ったとき、**内部告発した者を保護する**のが公益通報者保護法である。

| 項目 | 内容 |
| --- | --- |
| 保護される通報者 | 労働者、派遣労働者、役員、退職後1年以内の者など |
| 通報先 | **事業者内部**、**権限のある行政機関**、**その他の外部**（報道機関など）。外部ほど要件が厳しい |
| 保護の内容 | **解雇の無効**、降格・減給などの**不利益な取扱いの禁止** |
| 事業者の義務 | **内部公益通報に対応する体制の整備**（従業員301人以上は義務） |

**通報先によって要件が変わる**のがこの法律の構造である。内部通報は「不正があると思料する」だけでよいが、報道機関などへの通報は、内部通報すると証拠が隠滅される恐れがあるなどの**追加の要件**を満たす必要がある。これは、まず組織内で是正する機会を与えつつ、それが機能しない場合の逃げ道を確保するという設計になっている。

### 5.4 情報技術者が直面しやすい論点

| 論点 | 考え方 |
| --- | --- |
| **脆弱性の発見と公表** | 発見者は**まず開発者に通知**し、修正の機会を与える（**責任ある開示**）。日本では**情報セキュリティ早期警戒パートナーシップ**が届出の枠組みを定める（→ [11-2 情報セキュリティ管理](../11-security/11-2-情報セキュリティ管理.md)） |
| **ログ・通信内容の取扱い** | **通信の秘密**（電気通信事業法）に抵触しうる。運用上必要な範囲を超えた閲覧は許されない |
| **アルゴリズムの公平性** | 学習データの偏りが差別的な結果を生みうる。**説明可能性**の確保が求められる |
| **著作権・ライセンスの遵守** | OSSのライセンス条件（→ [5-5 オープンソースソフトウェア](../05-software/5-5-オープンソースソフトウェア.md)）を理解せずに組み込まない |

**責任ある開示**の考え方は、技術者倫理の典型例である。脆弱性を即座に公表すれば利用者は防御できるが、攻撃者も同時に知ることになる。黙っていれば攻撃は起きにくいが、修正もされない。そこで、**開発者に通知して修正の時間を与え、その後に公表する**という中間の手順が合意されている。法律で定まっているわけではなく、**関係者の利害を比較した結果として形成された規範**である点に、倫理の本質がよく表れている。

## この章のまとめ

- 標準には**デジュール（公的手続き）、デファクト（市場）、フォーラム（団体）**の三つの成立経路があり、相互に移行する。
- **国際標準適合の具体的な利点は、WTO政府調達協定に基づく政府調達市場への参入**。技術的優位の保証でも、特許の無償化でも、各国法規制の免除でもない。
- **標準必須特許はFRAND条件（公正・合理的・非差別的）でライセンスされる**。無償ではない。
- マネジメントシステム規格（27001、9001、14001、20000）は**いずれもPDCAを骨格とする共通構造**をもつ。
- **環境表示は「環境についての主張」**。排出量取引（排出枠）、グリーン購入法（調達）、グリーン電力証書（環境付加価値）とは扱う対象が異なる。
- 環境ラベルは**タイプI（第三者認証）、タイプII（自己宣言）、タイプIII（定量データの開示、良し悪しは判定しない）**に分かれる。
- 技術者倫理が必要なのは**情報の非対称性**があるから。公衆の利益の優先、能力の範囲内での受任、**責任ある開示**が核になる。
