# 2-3 プログラム言語

プログラム言語の分類と、代表的な言語の特徴を扱う。

言語の違いは単なる好みではなく、**何を自動化し、何をプログラマに委ねるか**という設計思想の違いである。メモリ管理を自分でやるのか処理系に任せるのか、型の誤りを実行前に弾くのか実行時に気づくのか──こうした選択が、その言語が得意とする領域を決めている。

午前Iの問3前後から出題されるが、16年で1問と出題は少ない。

出題が少ない分野のため、本章では過去問で問われた内容に加えて、言語の分類と特徴の整理を補っている。

## 1. 言語の分類

### 1.1 プログラミングパラダイム

| 分類 | 考え方 | 代表 |
| --- | --- | --- |
| 手続型 | 処理の手順を順に記述する | C、COBOL、FORTRAN |
| オブジェクト指向 | データと操作をまとめた「オブジェクト」の相互作用として記述する | Java、C++、C#（→ [12-2 設計](../12-system-development/12-2-設計.md)） |
| 関数型 | 関数の適用として記述し、状態の変更を避ける | Haskell、Lisp |
| 論理型 | 事実と規則を記述し、処理系が推論する | Prolog |
| スクリプト | 簡潔な記述で手軽に実行する | Python、Ruby、JavaScript、PHP |

### 1.2 型の扱い

| 分類 | 内容 |
| --- | --- |
| 静的型付け | コンパイル時に型を検査する。実行前に型の誤りを発見できる（Java、C、Go） |
| 動的型付け | 実行時に型が決まる。記述は簡潔だが、型の誤りは実行して初めて分かる（Python、Ruby、JavaScript） |

**静的型付けは安全性、動的型付けは記述の手軽さ**を優先した選択である。大規模で長期間保守するシステムでは前者が、短期間で書き換えるスクリプトでは後者が選ばれる傾向がある。

## 2. 言語処理系

| 処理系 | 動作 |
| --- | --- |
| **コンパイラ** | ソースコード全体を**事前に**機械語へ翻訳する。実行は速いが、翻訳に時間がかかる |
| **インタプリタ** | ソースコードを**逐次**解釈しながら実行する。すぐ試せるが実行は遅い |
| 中間言語方式 | 中間コード（バイトコード）に翻訳し、仮想マシンで実行する。Javaの方式 |
| JITコンパイラ | 実行時に、頻繁に使われる部分を機械語に翻訳する |

Javaが**中間言語方式**を採るのは、**「一度書けばどこでも動く」**ことを目的としたためである。機械語はCPUごとに異なるが、バイトコードは共通にできる。各環境に仮想マシン（JVM）を用意すれば、同じバイトコードがどこでも動く。実行速度の不利はJITコンパイラで補っている。

コンパイラ・インタプリタを含む開発支援ツールは [5-4 開発ツール](../05-software/5-4-開発ツール.md) で扱う。

## 3. 代表的な言語の特徴

| 言語 | 特徴 |
| --- | --- |
| C | ポインタで直接メモリを操作できる。OSや組込みで使われる |
| C++ | Cにオブジェクト指向を追加 |
| Java | 中間言語方式で環境非依存。**ブロックは `{ }` で囲む** |
| **Python** | **ブロックの範囲を指定する方法として特定の記号や予約語を用いず、等しい文字数の字下げを用いる**。AI・データ分析で広く使われる |
| **PHP** | Webのサーバサイド処理。**ブロックは `{ }` で囲む** |
| JavaScript | Webブラウザ上で動作する。Node.jsでサーバサイドにも使われる |
| Ruby | スクリプト言語。Webアプリケーション開発で使われる |

> **ブロックの範囲を指定する方法として特定の記号や予約語を用いず、等しい文字数の字下げを用いるという特徴をもつ**言語は **Python** である。

C、Java、PHPはいずれも `{ }` でブロックを囲む。Pythonだけが**字下げそのものを文法の一部にしている**。

この設計の意図は、**「見た目の構造」と「実際の構造」を必ず一致させる**ことにある。他の言語では、字下げがずれていても `{ }` が正しければ動いてしまうので、読み手が誤解する余地が残る。Pythonでは字下げが構造そのものなので、見た目どおりに動くことが保証される。その代わり、字下げの不統一（タブとスペースの混在など）が構文エラーになるという制約も生じる。

> **出題** プログラム言語の特徴: R4午前I問3

## 4. マークアップ言語とデータ記述言語

プログラム言語ではないが、同じ文脈で出題されるものを整理しておく。

| 言語 | 用途 |
| --- | --- |
| HTML | Webページの構造を記述する |
| **XML** | データの構造をタグで記述する。タグを自由に定義できる |
| JSON | データを簡潔に記述する。JavaScript由来で、Web APIで広く使われる |
| **SVG** | 図形をXML形式で記述する画像フォーマット（→ [8-1 マルチメディア技術](../08-information-media/8-1-マルチメディア技術.md)） |
| MathML | 数式をXML形式で記述する（→ [12-2 設計](../12-system-development/12-2-設計.md)） |
| XBRL | 財務情報をXML形式で記述する（→ [22-3 会計・財務](../22-corporate-activities/22-3-会計-財務.md)） |
| SQL | データベースへの問合せを記述する（→ [9-3 データ操作](../09-database/9-3-データ操作.md)） |
| VHDL / Verilog HDL | ハードウェア論理を記述する（→ [12-2 設計](../12-system-development/12-2-設計.md)） |

**XMLから派生した記述言語が多い**のは、XMLが「タグを自由に定義できる汎用の枠組み」だからである。数式でも図形でも財務諸表でも、その分野のタグを定義すれば、共通のパーサで読める。この汎用性と引き換えに記述が冗長になるため、Web APIのような軽さが求められる場面ではJSONに置き換えられてきた。

## この章のまとめ

- 言語の選択は**何を自動化し、何をプログラマに委ねるか**の違い。静的型付けは安全性、動的型付けは手軽さを優先する。
- **Pythonは字下げでブロックを表す**唯一の主要言語。C・Java・PHPは `{ }` を使う。
- **Javaの中間言語方式は環境非依存を実現するため**。速度の不利はJITコンパイラで補う。
- XMLから派生した記述言語（SVG、MathML、XBRL）は、**タグを自由に定義できる汎用性**に由来する。
