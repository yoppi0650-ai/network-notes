# 2-2 アルゴリズム

問題を解く**手順そのもの**を扱う。整列（ソート）、探索、再帰、アルゴリズムの設計戦略が主な題材である。

この分野で問われるのは、**アルゴリズムの名前と特徴の対応**と、**与えられた手順を正確にトレースする力**である。前者は「ヒープソートの説明はどれか」といった形で、後者は「入替えは何回行われるか」「2回目の分割が終わった状態はどれか」といった形で出る。後者は知識ではなく**手を動かせば必ず解ける**問題なので、確実に取りたい。

午前Iの問1・問3前後から出題される。16年で8問。

## 1. 計算量

アルゴリズムの効率は、データ件数 $n$ に対して処理時間がどう増えるかで評価する。これを**オーダ記法**で表す。

| オーダ | 増え方 | 例 |
| --- | --- | --- |
| $O(1)$ | 件数に依存しない | ハッシュ表の探索（→ [2-1 データ構造](2-1-データ構造.md)） |
| $O(\log n)$ | ゆるやかに増える | 2分探索、2分探索木 |
| $O(n)$ | 比例して増える | 線形探索 |
| $O(n \log n)$ | やや速く増える | クイックソート、マージソート、ヒープソート |
| $O(n^2)$ | 急激に増える | バブルソート、選択ソート、挿入ソート |

**件数が少ないうちは差が出ないが、増えると決定的な差になる**。$n = 1{,}000{,}000$ のとき、$O(n \log n)$ はおよそ2,000万回の操作で済むが、$O(n^2)$ は1兆回になる。実用上、大量データを扱うなら $O(n^2)$ のアルゴリズムは選べない。

## 2. 探索アルゴリズム

| 手法 | 前提 | 平均計算量 |
| --- | --- | --- |
| **線形探索** | なし（未整列でもよい） | $O(n)$ |
| **2分探索** | **整列されていること** | $O(\log n)$ |
| **ハッシュ表探索** | ハッシュ関数と表 | $O(1)$ |

### 2.1 探索表の構成法と手法の対応

> 探索表の構成法を例とともに a〜c に示す。探索の**平均計算量が最も小さい**探索手法の組合せはどれか。
>
> - a：**コード順に格納**した探索表
> - b：コードの**使用頻度順に格納**した探索表
> - c：コードから求めたハッシュ値の**格納位置に格納**した探索表

**構成法が、使える探索手法を決める**という関係を読み取る問題である。

| 構成法 | 使える最速の手法 | 理由 |
| --- | --- | --- |
| **a：コード順** | **2分探索** $O(\log n)$ | **整列されているので2分探索が使える** |
| **b：使用頻度順** | **線形探索** $O(n)$ | 順序がコード順でないので2分探索は使えない。ただし頻度の高いものが前にあるので線形探索でも早く見つかりやすい |
| **c：ハッシュ値の位置** | **ハッシュ表探索** $O(1)$ | ハッシュ関数で一発で位置が決まる |

したがって組合せは **a:2分探索、b:線形探索、c:ハッシュ表探索** となる。

**bが線形探索しか使えない**点が要点である。使用頻度順に並べるのは「よく使うものを前に置いて、線形探索の平均回数を減らす」という最適化であって、2分探索を可能にするものではない。2分探索は**キーの大小で並んでいること**を前提に、中央と比較して範囲を半分に絞る手法なので、頻度順では成立しない。

> **出題** 探索アルゴリズムの計算量: H22午前I問3

## 3. 整列アルゴリズム

### 3.1 主なアルゴリズムの特徴

**名前と説明の対応**がそのまま出題される。

| 手法 | 説明 | 平均計算量 |
| --- | --- | --- |
| **バブルソート（交換法）** | **隣り合う要素を比較して、大小の順が逆であれば、それらの要素を入れ替えるという操作を繰り返す** | $O(n^2)$ |
| 選択ソート | 未整列部分から最小値を選んで先頭に置くことを繰り返す | $O(n^2)$ |
| 挿入ソート | 整列済み部分の適切な位置に次の要素を挿入する | $O(n^2)$ |
| **シェルソート** | **ある間隔おきに取り出した要素から成る部分列をそれぞれ整列し、更に間隔を詰めて同様の操作を行い、間隔が1になるまで繰り返す** | $O(n^{1.2})$ 程度 |
| **クイックソート** | **中間的な基準値（ピボット）を決めて、それよりも大きな値を集めた区分と小さな値を集めた区分に要素を振り分ける。次にそれぞれの区分の中で同様な処理を繰り返す** | $O(n \log n)$ |
| **ヒープソート** | **未整列の部分を順序木（ヒープ）にし、そこから最小値を取り出して整列済の部分に移す。この操作を繰り返して、未整列の部分を縮めていく** | $O(n \log n)$ |
| マージソート | 分割してそれぞれ整列し、併合する | $O(n \log n)$ |

**ヒープソートの決め手は「順序木にする」**という記述である。ヒープ（親が子より常に小さい、または大きい木）を作れば、根が常に最小値（または最大値）になる。根を取り出して木を再構成する、を繰り返すのがヒープソートである。1回の取り出しと再構成が $O(\log n)$、それを $n$ 回行うので $O(n \log n)$ になる。

誤答は互いの説明を入れ替えてくるので、**キーワードで紐付ける**とよい。「隣り合う」ならバブルソート、「間隔」ならシェルソート、「基準値で振り分け」ならクイックソート、「順序木」ならヒープソートである。

### 3.2 クイックソートのトレース

> 配列に格納されたデータ **2, 3, 5, 4, 1** に対してクイックソートを用いて昇順に並べ替える。**2回目の分割が終わった状態**はどれか。ここで、分割は基準値より小さい値と大きい値のグループに分けるものとする。また、分割のたびに基準値はグループ内の配列の**左端の値**とし、グループ内の配列の値の順番は元の配列と同じとする。

手順どおりにトレースする。

**1回目の分割**：全体 `2, 3, 5, 4, 1` の左端 **2** を基準値とする。

- 2より小さい：`1`
- 2より大きい：`3, 5, 4`（元の順番を保つ）

結果は **`1, 2, 3, 5, 4`** となる。

**2回目の分割**：分割されたグループのうち、まだ整列されていないものを処理する。`1` は要素1個なので分割不要。次のグループ `3, 5, 4` の左端 **3** を基準値とする。

- 3より小さい：なし
- 3より大きい：`5, 4`（元の順番を保つ）

結果は **`1, 2, 3, 5, 4`** のままである。

したがって2回目の分割が終わった状態は **`1, 2, 3, 5, 4`** となる。

**注意点**は、クイックソートは**分割するだけで、グループ内は並べ替えない**ことである。「2回目の分割が終わった時点では、まだ 5, 4 の順序が逆のまま」という状態を正しく追えるかが問われている。完全に整列されるのは、すべてのグループが要素1個になるまで分割を繰り返したあとである。

### 3.3 入替え回数のトレース

> 未整列の配列 $a[1] \sim a[6]$ の値がそれぞれ **21, 5, 53, 71, 3, 17** の場合、流れ図において $a[j-1]$ と $a[j]$ の値の入替えは何回行われるか。

$a[j-1]$ と $a[j]$ を比べて入れ替えるのは、**隣接交換（バブルソート系）**である。この種の問題では、**「入替えが起きるのは、どういう条件のときか」を考えると見通しがよくなる**。

隣接交換で入れ替えが起きるのは、**元の並びで「前にあるのに値が大きい」ペアがあるとき**である。このようなペアの総数を**転倒数**といい、**隣接交換による入替え回数は転倒数に等しい**。

元の並び `21, 5, 53, 71, 3, 17` の転倒数を数える。各要素について、**自分より後ろにある自分より小さい値の個数**を数える。

| 要素 | 後ろにある小さい値 | 個数 |
| --- | --- | --- |
| 21 | 5, 3, 17 | 3 |
| 5 | 3 | 1 |
| 53 | 3, 17 | 2 |
| 71 | 3, 17 | 2 |
| 3 | なし | 0 |
| 17 | なし | 0 |
| | **合計** | **8** |

入替えは **8回**である。

ただし**この数え方が使えるのは、流れ図が完全な隣接交換を行っている場合に限る**。試験では流れ図が与えられるので、まずは**素直にトレースする**のが確実で、転倒数は検算に使うとよい。

> **出題** 整列アルゴリズムのトレース: H25午前I問3 ｜ ヒープソート: H28午前I問3 ｜ クイックソート: R5午前I問3

## 4. 再帰

**再帰**とは、関数が自分自身を呼び出すことで問題を解く手法である。

> `fact(n)` は、非負の整数 $n$ に対して $n$ の階乗を返す。`fact(n)` の再帰的な定義はどれか。

正しい定義は、

```
if n = 0 then return 1 else return n × fact(n - 1)
```

再帰の定義で確認すべき点は2つある。

- **終了条件（ベースケース）が正しいか**：$0! = 1$ なので、$n = 0$ のとき **1** を返す。**0 を返す定義では、どんな $n$ でも結果が0になってしまう**（最後に0を掛けるため）。
- **再帰呼出しが終了条件に近づくか**：$n - 1$ と減っていくので、いずれ $n = 0$ に到達する。**$n + 1$ では無限に増え続けて終わらない**。

誤答はこの2点をそれぞれ崩したものになっている。

| 定義 | 誤りの理由 |
| --- | --- |
| `n = 0` で **0** を返し、`fact(n-1)` を呼ぶ | 結果が常に0になる |
| `n = 0` で 0 を返し、`fact(n+1)` を呼ぶ | 両方とも誤り |
| `n = 0` で 1 を返し、**`fact(n+1)`** を呼ぶ | 終了条件に近づかず、無限再帰になる |

**「終了条件の値」と「再帰呼出しの向き」の2点を確認する**のが、再帰の問題を解く定石である。

> **出題** 再帰的定義: H29午前I問3

## 5. アルゴリズムの設計戦略

問題の解き方には、いくつかの典型的な戦略がある。

| 戦略 | 考え方 |
| --- | --- |
| **分割統治法** | **全体を幾つかの小さな問題に分割して、それぞれの小さな問題を独立に処理した結果をつなぎ合わせて、最終的に元の問題を解決する** |
| **貪欲法（greedy）** | **問題をある尺度に沿って分解し、各時点で最良の解を選択し、これを繰り返すことによって全体の解を得る** |
| **分枝限定法** | **起こり得る全てのデータを組み合わせ、それぞれの解を調べることによって、データの組合せのうち無駄なものを除き、実際に調べる組合せ数を減らす** |
| **動的計画法** | 部分問題の解を記録して再利用し、重複計算を避ける |
| 近似解法 | **粗い解を出し、それを逐次改良して精度の良い解を得る** |

**分割統治法の要点は「分割 → 独立に処理 → 統合」**という3段階である。クイックソートもマージソートもこの戦略に基づいており、だからこそ $O(n \log n)$ という計算量になる。$n$ 個の問題を半分ずつに分けていけば深さは $\log n$ になり、各深さで $n$ 回の処理をするので積が $n \log n$ になる。

**貪欲法**は「各時点で最良を選ぶ」単純な戦略だが、**必ずしも全体最適になるとは限らない**。目先の最善が将来の選択肢を狭めることがあるためである。一方、分割統治法や動的計画法は構造的に最適解を保証できる場合がある。この違いが戦略の選択を分ける。

> **出題** 分割統治法: R3午前I問3

## 6. 反復法の計算

**二分法**は、解が含まれる区間を半分ずつ狭めていく数値計算の手法である。[2. 探索アルゴリズム](#2-探索アルゴリズム) の2分探索と同じ原理を、連続量に適用したものになる。

> $0 \leq x \leq 1$ の範囲で単調に増加する連続関数 $f(x)$ が $f(0) < 0 \leq f(1)$ を満たすときに、区間内で $f(x) = 0$ である $x$ を近似的に求めるアルゴリズムにおいて、**(2) は何回実行されるか**。
>
> 1. $x_0 \leftarrow 0$、$x_1 \leftarrow 1$ とする
> 2. $x \leftarrow \dfrac{x_0 + x_1}{2}$ とする
> 3. $x_1 - x < 0.001$ ならば $x$ を近似値として終了する
> 4. $f(x) \geq 0$ ならば $x_1 \leftarrow x$、そうでなければ $x_0 \leftarrow x$ とする
> 5. (2) に戻る

**1回の反復で区間が半分になる**。初期の区間幅は1なので、$k$ 回実行後の区間幅は $\dfrac{1}{2^k}$ である。

終了条件は $x_1 - x < 0.001$ である。$x$ は区間の中点なので、$x_1 - x$ は**そのときの区間幅の半分**にあたる。$k$ 回目の実行で $x_1 - x = \dfrac{1}{2^k}$ となるので、

$$ \frac{1}{2^k} < 0.001 \quad \Longleftrightarrow \quad 2^k > 1{,}000 $$

$2^9 = 512$、$2^{10} = 1{,}024$ なので、$k = 10$ で初めて条件を満たす。よって **10回**である。

**$2^{10} \approx 1{,}000$ という関係**は情報処理の計算で繰り返し使う。1 kバイト $= 2^{10}$ バイト、1 Mバイト $= 2^{20}$ バイトという対応もここから来ている。

二分法が強力なのは、**反復1回あたりの計算は軽いのに、精度が指数的に上がる**点である。精度を10倍上げるのに必要な反復は3〜4回増えるだけで済む。1,000分の1の精度に10回、100万分の1の精度でも20回で到達する。

> **出題** 二分法の反復回数: H28午前I問1、R7午前I問1

## この章のまとめ

- 計算量は $O(1) < O(\log n) < O(n) < O(n \log n) < O(n^2)$。**件数が増えると決定的な差になる**。
- 探索手法は**構成法が決める**。コード順なら2分探索、使用頻度順なら線形探索、ハッシュ値の位置ならハッシュ表探索。
- 整列はキーワードで紐付ける。**「隣り合う」＝バブル、「間隔」＝シェル、「基準値で振り分け」＝クイック、「順序木」＝ヒープ**。
- **クイックソートは分割するだけで、グループ内は並べ替えない**。トレース問題では途中の状態を正確に追う。
- 隣接交換の入替え回数は**転倒数（前にあるのに値が大きいペアの数）**に等しい。
- 再帰は**終了条件の値と、再帰呼出しが終了条件に近づくか**の2点を確認する。
- **分割統治法は「分割 → 独立処理 → 統合」**。貪欲法は各時点の最良を選ぶが全体最適とは限らない。
- 二分法は**1回で区間が半分**になる。$2^{10} \approx 1{,}000$ を使って反復回数を求める。
