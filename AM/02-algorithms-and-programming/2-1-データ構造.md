# 2-1 データ構造

データを**どう並べて保持するか**を扱う。配列、リスト、スタック、キュー、木、ハッシュ表が主な題材である。

データ構造の選択は、そのまま**どの操作が速くなり、どの操作が遅くなるか**を決める。配列は添字でどこへでも一瞬で行けるが、途中への挿入には全体をずらす必要がある。リストは挿入が一瞬だが、$n$ 番目を見るには先頭から辿るしかない。**万能のデータ構造は存在しない**ので、「この処理では何の操作が多いか」から逆算して選ぶことになる。本章はその判断の材料を与える。

午前Iの問3・問4前後から出題される。16年で14問と、分野2のなかで最も出題が多い。

## 1. 配列とリスト

### 1.1 2つの実現方法の比較

同じ「順序をもつデータの並び（リスト）」でも、配列で実現するかポインタで実現するかで性質が大きく変わる。

| | 配列による実現 | ポインタによる実現（連結リスト） |
| --- | --- | --- |
| メモリ | **実際の要素数にかかわらず、最大個数分の領域を確保する。使用されない領域が発生する可能性がある** | 要素ごとに確保。ただし**次の要素を指すポインタの領域が別途必要** |
| $i$ 番目の参照 | 添字で**直接アクセスできる**（一定時間） | **先頭から順にたどる**ので要素数に比例した時間がかかる |
| 途中への挿入・削除 | 後続の要素をずらす必要があり、要素数に比例した時間がかかる | **挿入位置が分かっていれば、ポインタの張替えだけで一定時間** |

配列の特徴として出題されたのは、

> **リストにある実際の要素数にかかわらず、リストに入れられる要素の最大個数に対応した領域を確保し、実際には使用されない領域が発生する可能性がある。**

残りの選択肢はいずれも**ポインタによる実現の特徴**である。

- 「中間要素を参照するには先頭から順にたどる」→ 連結リスト
- 「次の要素を指し示すための領域が別途必要」→ 連結リスト
- 「挿入位置が分かれば一定時間で挿入できる」→ 連結リスト

**「領域を先に確保するのが配列、つなぎ方の情報を持つのがポインタ」**と整理すると、それぞれの長所短所が自然に導ける。

### 1.2 単方向リストの操作コスト

連結リストでは、**ポインタをたどる回数**が操作のコストになる。

> 先頭ポインタと末尾ポインタをもち、多くのデータがポインタでつながった**単方向**の線形リストの処理のうち、ポインタをたどる回数が**最も多い**ものはどれか。

答えは **末尾のデータを削除する処理**である。

| 処理 | たどる回数 |
| --- | --- |
| 先頭にデータを追加 | 先頭ポインタを使うだけ。**たどらない** |
| 先頭のデータを削除 | 先頭ポインタを使うだけ。**たどらない** |
| 末尾にデータを追加 | 末尾ポインタを使うだけ。**たどらない** |
| **末尾のデータを削除** | **先頭から最後尾の1つ前まで全部たどる必要がある** |

末尾削除だけが重いのは、**単方向リストでは「1つ前の要素」を知る手段がない**からである。末尾を削除したら、新しい末尾（元の末尾の1つ前）のポインタを NULL にし、末尾ポインタを張り替えなければならない。しかしその「1つ前の要素」は、先頭からたどるしか見つけられない。

**末尾ポインタを持っていても末尾削除は速くならない**、という点がこの問題の要点である。これを解決するには**双方向リスト**（各要素が前後両方のポインタを持つ）にする必要がある。

### 1.3 計算量の比較

> $n$ 個の要素から成る連結リストに対して、**新たな要素の末尾への追加**に要する時間を $f(n)$、**末尾の要素の削除**に要する時間を $g(n)$ とする。$n$ が非常に大きいとき、$\dfrac{g(n)}{f(n)}$ の挙動はどうなるか。
>
> - 実装方法1：先頭を指すポインタ `front` だけをもつ
> - 実装方法2：`front` に加えて末尾を指すポインタ `rear` をもつ

それぞれの計算量を整理する。

| | 末尾への追加 $f(n)$ | 末尾の削除 $g(n)$ | $g(n)/f(n)$ |
| --- | --- | --- | --- |
| **実装1**（frontのみ） | 先頭からたどる：$n$ に比例 | 先頭からたどる：$n$ に比例 | **ほぼ1** |
| **実装2**（front と rear） | rearを使う：**一定時間** | 先頭からたどる：$n$ に比例 | **ほぼ $n$ に比例** |

**実装1では両方とも $n$ に比例するので比はほぼ1**、**実装2では追加だけが速くなるので比は $n$ に比例して大きくなる**。

この結果が示しているのは、[1.2](#12-単方向リストの操作コスト) と同じことである。**末尾ポインタは「末尾への追加」は速くするが、「末尾の削除」は速くしない**。前者は末尾そのものを触ればよいが、後者は1つ前が必要だからである。

> **出題** 連結リストの計算量: H21午前I問3 ｜ 単方向リストの操作: R1午前I問4 ｜ 配列によるリストの実現: R4午前I問2

## 2. スタックとキュー

| 構造 | 取り出す順序 | 呼び方 |
| --- | --- | --- |
| **スタック** | **最後に入れたものから** | LIFO (Last In First Out) |
| **キュー** | **最初に入れたものから** | FIFO (First In First Out) |

### 2.1 スタックの実現

> 配列を用いてスタックを実現する場合の構成要素として、**最低限必要なもの**はどれか。

答えは **スタックに最後に入った要素を示す添字の変数**（スタックポインタ）である。

スタックは**片方の端でしか出し入れしない**ので、その位置さえ分かれば操作できる。`push` なら添字を1増やしてそこに書き、`pop` ならそこを読んで添字を1減らす。「最初に入った要素の位置」は配列の先頭に固定なので、わざわざ覚える必要がない。

キューを配列で実現する場合は、**取り出す側と入れる側が別の端**になるので、先頭と末尾の両方の添字が必要になる。この違いがスタックとキューの実装の差になる。

### 2.2 出力順序の数え上げ

> A, B, C の順序で入力されるデータがある。各データについてスタックへの挿入と取出しを1回ずつ行うことができる場合、データの出力順序は何通りあるか。

**挿入（push）と取出し（pop）の順番を組み合わせる**問題である。「A, B, C の順に入力される」という制約があるので、pushの順序は固定され、各時点でpushするかpopするかの選択だけが自由になる。

可能な出力順序を列挙する。

| 操作の並び | 出力 |
| --- | --- |
| push A, pop, push B, pop, push C, pop | **A B C** |
| push A, pop, push B, push C, pop, pop | **A C B** |
| push A, push B, pop, pop, push C, pop | **B A C** |
| push A, push B, pop, push C, pop, pop | **B C A** |
| push A, push B, push C, pop, pop, pop | **C B A** |

**5通り**である。

**C A B が作れない**ことが答えを 6 ではなく 5 にしている。C を最初に出すには A, B, C をすべて push する必要があり、その時点でスタックは下から A, B, C の順になっている。C を pop した次に出せるのは B だけで、A を先に出すことはできない。

この「作れない順序がある」という性質が、スタックがLIFOであることの直接の帰結である。一般に $n$ 個の場合の通り数は**カタラン数** $\dfrac{1}{n+1}{}_{2n}\mathrm{C}_n$ になり、$n=3$ なら $\dfrac{1}{4} \times {}_6\mathrm{C}_3 = \dfrac{20}{4} = 5$ と一致する。

### 2.3 逆ポーランド表記法

**逆ポーランド表記法（後置表記法）**は、演算子を被演算子の**後ろ**に書く記法である。スタックを使えば括弧なしで計算できるため、コンパイラや電卓の内部で使われる。

**変換の手順**は、**演算の順序どおりに「被演算子、被演算子、演算子」の形に並べ替える**ことである。

**例題1**：$A + B \times C$ を変換する。

まず演算の優先順位から、$\times$ が先、$+$ が後である。

1. $B \times C$ → `BC×`
2. $A + (\text{上の結果})$ → `A` `BC×` `+` → **`ABC×+`**

**例題2**：$Y = (A+B) \times (C - (D \div E))$ を変換する。

内側から順に処理する。

| 部分式 | 後置表記 |
| --- | --- |
| $A + B$ | `AB+` |
| $D \div E$ | `DE÷` |
| $C - (D \div E)$ | `C` `DE÷` `-` → `CDE÷-` |
| $(A+B) \times (C - (D \div E))$ | `AB+` `CDE÷-` `×` → `AB+CDE÷-×` |
| $Y = \cdots$ | `Y` `AB+CDE÷-×` `=` → **`YAB+CDE÷-×=`** |

**検算のコツ**は、**演算子の直前にある2つの項が、その演算子の被演算子になっているか**を確かめることである。`DE÷` なら「D を E で割る」であって「E を D で割る」ではない。**順序が逆の選択肢**（`ED÷` など）が必ず用意されているので注意する。

> **出題** スタックの実現: H24午前I問3 ｜ スタックの出力順序: R3午前I問2、R7午前I問3 ｜ 逆ポーランド表記法: H22午前I問1、H23午前I問1

## 3. 木構造

**木**は、親子関係をもつ階層的なデータ構造である。節（ノード）と枝（エッジ）から成り、最上位を**根**、末端を**葉**という。

### 3.1 2分木の走査

各節が子を2つまでもつ木を**2分木**という。すべての節を訪れる順序を**走査（トラバーサル）**といい、**節自身を出力するタイミング**で3種類に分かれる。

| 走査 | 順序 |
| --- | --- |
| **先行順（前順）** | **自分** → 左 → 右 |
| 中間順（間順） | 左 → **自分** → 右 |
| **後行順（後順）** | 左 → 右 → **自分** |

式を表す2分木では、**後行順に走査すると逆ポーランド表記になる**。節に演算子、葉に被演算子を置けば、「左の結果、右の結果、演算子」の順に出力されるからである。

### 3.2 再帰処理のトレース

> 各ノードがもつデータを出力する再帰処理 `f(ノード n)` を次のように定義した。図の2分木の根から始めたときの出力はどれか。
>
> 1. ノード n の**右**に子ノード r があれば、`f(ノード r)` を実行
> 2. ノード n の**左**に子ノード l があれば、`f(ノード l)` を実行
> 3. 子ノードの再帰処理が終わるか子ノードがなければ、**ノード自身のデータを出力**
> 4. 終了

定義を読み解くと、**「右 → 左 → 自分」**の順である。通常の後行順（左 → 右 → 自分）と**左右が入れ替わっている**点が要点になる。

したがって出力は、**後行順の出力を左右反転させたもの**になる。式木であれば、通常の後行順が逆ポーランド表記 `ABC×DE-÷+` になるところ、この処理では **`ED-CB×÷A+`** のように、各段階で右の部分木が先に出力される。

**この種の問題は、定義を日本語で一文にしてからトレースする**のが確実である。「右、左、自分の順に出力する」と言い換えてしまえば、あとは図をたどるだけになる。選択肢には通常の後行順や先行順の結果が並ぶので、左右の順序に注意して選ぶ。

### 3.3 その他の木

| 木 | 特徴 |
| --- | --- |
| 2分探索木 | 左の子 < 自分 < 右の子 の関係を保つ。探索が $O(\log n)$ |
| 平衡木（AVL木、B木） | 木の高さが偏らないよう調整する。データベースのインデックスで使われる（→ [9-2 データベース設計](../09-database/9-2-データベース設計.md)） |
| ヒープ | 親が子より常に大きい（または小さい）。ヒープソートで使う（→ [2-2 アルゴリズム](2-2-アルゴリズム.md)） |

> **出題** 2分木の再帰的走査: R6午前I問3

## 4. ハッシュ表

**ハッシュ表**は、キーを**ハッシュ関数**で格納位置に変換して、**一度の計算で目的のデータに到達する**データ構造である。

### 4.1 理論的な探索時間

> ハッシュ表の理論的な探索時間を示すグラフはどれか。ここで、複数のデータが同じハッシュ値になることはないものとする。

衝突がない前提なら、**データ件数が増えても探索時間は変わらない**。キーからハッシュ関数で位置を計算し、そこを直接見るだけだからである。グラフは**水平な直線**になる。

これがハッシュ表の最大の利点である。線形探索は $O(n)$、2分探索は $O(\log n)$ で件数とともに遅くなるが、ハッシュ表は $O(1)$ で**件数に依存しない**。

### 4.2 衝突

異なるキーが同じハッシュ値になることを**衝突（シノニム）**という。

> 自然数をキーとするデータを、ハッシュ表を用いて管理する。キー $x$ のハッシュ関数を $h(x) = x \bmod n$ とすると、キー $a$ と $b$ が衝突する条件はどれか。

衝突の条件は $a \bmod n = b \bmod n$ である。これは「$a$ と $b$ を $n$ で割った余りが等しい」という意味なので、**差が $n$ の倍数**であることと同値になる。

$$ a \bmod n = b \bmod n \iff \mathbf{a - b\ \text{が}\ n\ \text{の倍数}} $$

$a = 17$、$b = 7$、$n = 5$ で確かめると、$17 \bmod 5 = 2$、$7 \bmod 5 = 2$ で衝突し、$a - b = 10$ は確かに5の倍数である。

**「$a+b$ が $n$ の倍数」ではない**点に注意する。選択肢には和と差、倍数の向きを入れ替えたものが並ぶ。

### 4.3 例題：ASCIIコードの下1桁

> キーが小文字のアルファベット1文字であるデータを、大きさが10のハッシュ表に格納する。ハッシュ関数として、**アルファベットのASCIIコードを10進表記したときの1の位の数**を用いる。衝突が起こるキーの組合せはどれか。

ASCIIコードはアルファベット順に連続した値が割り当てられている（`a` = 97、`b` = 98、…）。1の位が一致するのは、**コードの差が10の倍数**のときである。つまり**アルファベット順で10文字離れた組**が衝突する。

| 組 | 文字の距離 | 衝突するか |
| --- | --- | --- |
| a と i | 8 | ✗ |
| b と r | 16 | ✗ |
| c と l | 9 | ✗ |
| **d と x** | **20** | **○** |

d は4番目、x は24番目で差は20（10の倍数）なので衝突する。**個々のASCIIコードを覚えていなくても、「差が10の倍数か」だけで判定できる**。

### 4.4 例題：除数を求める

> 自然数を除数とした剰余を返すハッシュ関数がある。値が **571、1168、1566** である三つのキーのハッシュ値がすべて衝突した。このとき使用した除数は幾つか。

[4.2](#42-衝突) の条件から、**どの2つの差も除数の倍数**でなければならない。差を計算する。

$$ 1168 - 571 = 597 $$
$$ 1566 - 1168 = 398 $$
$$ 1566 - 571 = 995 $$

この3つすべてを割り切る数が除数である。選択肢（193、197、199、211）で試す。

$$ 597 = 199 \times 3, \qquad 398 = 199 \times 2, \qquad 995 = 199 \times 5 $$

すべて **199** で割り切れる。したがって除数は **199** である。

**解き方の手順は、差を取ってから選択肢で割ってみる**ことである。元の値をそれぞれ割って余りを比べるより、差を使うほうが計算が軽い。

### 4.5 衝突への対処

実際のハッシュ表では衝突は避けられないので、対処法が用意されている。

| 方法 | 内容 |
| --- | --- |
| チェイン法（連鎖法） | 同じハッシュ値のデータを連結リストでつなぐ |
| オープンアドレス法 | 衝突したら別の空き位置を探す（線形探索法、2次探索法など） |

衝突が増えるとハッシュ表の性能は $O(1)$ から劣化していく。これを防ぐため、**表の大きさに余裕を持たせる**（使用率を一定以下に保つ）ことと、**値が偏らないハッシュ関数を選ぶ**ことが設計の要点になる。[4.3](#43-例題asciiコードの下1桁) のような「下1桁を使う」単純な関数は、キーの分布に偏りがあると衝突が多発する。

> **出題** ハッシュ表の衝突条件: H23午前I問3、H25午前I問2 ｜ ハッシュ関数と衝突: H27午前I問3、H30午前I問9 ｜ ハッシュ表の探索時間: R5午前I問6

## この章のまとめ

- **配列は最大個数分の領域を先に確保し、添字で直接アクセスできる**。**連結リストはポインタの領域が別途必要で、$i$ 番目の参照は先頭からたどる**。
- 単方向リストで重いのは**末尾の削除**。1つ前の要素を知る手段がないため、末尾ポインタがあっても速くならない。
- **スタックは最後に入った要素の添字だけで実現できる**。3個のデータの出力順序は**5通り**（`C A B` は作れない）。
- **逆ポーランド表記は「被演算子、被演算子、演算子」の順**に並べ替える。被演算子の順序を入れ替えた誤答に注意する。
- 2分木の走査は**自分を出力するタイミング**で分かれる。再帰処理の問題は、定義を「右、左、自分の順」のように一文に言い換えてからトレースする。
- **ハッシュ表の探索時間はデータ件数に依存しない（グラフは水平）**。**衝突の条件は「キーの差が除数の倍数」**であり、差を使って解く。
