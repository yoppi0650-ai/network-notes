# 17-3 ソリューションビジネス

情報システムを**サービスとして提供する形態**を扱う。クラウドサービス、アウトソーシング、ソリューションの提供形態が主な題材である。

この分野を貫く変化は、**「所有」から「利用」へ**である。かつては自社でハードウェアを買い、ソフトウェアを導入し、運用要員を抱えるのが当然だった。いまは必要なときに必要なだけ外部のサービスを使う形が主流になっている。本章の技術と用語は、この転換を支えるものとして理解できる。

午前Iの問24前後から出題される。16年で1問。

出題が少ない分野のため、本章では過去問で問われた内容に加えて、提供形態の整理を補っている。

## 1. サービスの提供形態

| 形態 | 内容 |
| --- | --- |
| **オンプレミス** | 自社でハードウェア、ネットワークなどの環境を用意し、業務パッケージを導入して利用する運用形態 |
| **ホスティング** | 事業者が用意したサーバを借りる |
| **ハウジング** | 自社のサーバを事業者の施設に設置する |
| **クラウドサービス** | インターネット経由で、必要なときに必要なだけ利用する |
| **パブリッククラウド** | 不特定多数が共用する |
| **プライベートクラウド** | 自社専用に構築する |
| **コミュニティクラウド** | **業種や事業内容などが共通する複数の企業や組織が共同でデータセンタを運用し、インターネットを通じて各種サービスを利用する** |

クラウドのサービスモデル（IaaS、PaaS、SaaS、FaaS、DaaS）は [4-1 システムの構成](../04-system-components/4-1-システムの構成.md) で扱う。

**ホスティングとハウジングの違い**は、**サーバの所有者が誰か**である。ホスティングは事業者のサーバを借り、ハウジングは自社のサーバを置く場所（と電源・空調・回線）を借りる（→ [15-5 ファシリティマネジメント](../15-service-management/15-5-ファシリティマネジメント.md)）。

## 2. プロビジョニング

> クラウドサービスなどの提供を迅速に実現するための**プロビジョニング**の説明はどれか。

答えは、

> **利用者の需要を予想し、ネットワーク設備やシステムリソースなどを計画的に調達して強化し、利用者の要求に応じたサービスを提供すること。**

**プロビジョニング（provisioning）は「供給・準備」**を意味する。利用者が「使いたい」と言ったときに、すぐ使える状態を整えておく活動である。

クラウドサービスの価値は**「すぐ使える」こと**にある。従来なら機器の調達に数週間、構築に数日かかっていたものが、クラウドでは数分で用意される。これを支えているのが、**事前に資源を確保し、要求に応じて即座に割り当てる**仕組み、すなわちプロビジョニングである。

誤答として並ぶ記述との区別を押さえる。

| 記述 | 実際は何か |
| --- | --- |
| 企画、設計、開発、導入、保守などのサービスを、一貫して又は部分的に提供する | **SI（システムインテグレーション）** |
| 業種や事業内容が共通する複数の企業が共同でデータセンタを運用し、サービスを利用する | **コミュニティクラウド** |
| 自社でハードウェア、ネットワークなどの環境を用意し、業務パッケージを導入して利用する | **オンプレミス** |
| **利用者の需要を予想し、設備やリソースを計画的に調達して強化し、要求に応じたサービスを提供する** | **プロビジョニング** |

なお、サーバ構成を自動化する**サーバプロビジョニングツール**（→ [13-3 開発環境管理](../13-software-development-management/13-3-開発環境管理.md)）も同じ語に由来する。どちらも「使える状態を準備する」という意味で一貫している。

需要予測に基づいて資源を確保するという点では、[4-2 システムの評価指標](../04-system-components/4-2-システムの評価指標.md) のキャパシティプランニングと同じ発想に立っている。

## 3. ソリューションの類型

**ソリューション**とは、顧客の経営課題を解決するために、製品・技術・サービスを組み合わせて提供することである。

| 類型 | 内容 |
| --- | --- |
| 業種別ソリューション | 金融、製造、流通など、特定業種の課題に特化 |
| 業務別ソリューション | 人事、会計、CRMなど、特定業務に特化 |
| **SI（システムインテグレーション）** | **企画、設計、開発、導入、保守などを一貫して、または部分的に提供する** |
| アウトソーシング | 業務やシステム運用を外部に委託する（→ [17-2 業務プロセス](17-2-業務プロセス.md) のBPO） |
| **ASP** | アプリケーションをネットワーク経由で提供する。SaaSの先駆け |

### 3.1 ソリューションビジネスの性質

ソリューションビジネスが単なる製品販売と異なるのは、**顧客の課題を特定するところから始まる**点である。製品を売るのではなく、「顧客の経営課題の達成に向けて、情報技術と専門家によるプロフェッショナルサービスを通して支援する」のがソリューションの定義になる。

この性質から、**提供側に求められる能力が変わる**。製品知識だけでなく、顧客の業界と業務を理解し、課題を分析する能力が要る。[17-1 情報システム戦略](17-1-情報システム戦略.md) で見たバランススコアカードの設問で、ITベンダの「学習と成長」のKPIとして**「社内要員30名をITのプロフェッショナルとして育成する」**が挙げられていたのは、まさにこの構造を反映している。

### 3.2 クラウド利用に伴う検討事項

クラウドサービスを利用する際には、オンプレミスにはないリスクを評価する必要がある。

| 観点 | 検討事項 |
| --- | --- |
| **事業者の継続性** | **事業者が撤退・破綻すれば、預けた情報が失われうる**（→ [16-1 システム監査](../16-system-audit/16-1-システム監査.md)） |
| データの所在 | データがどの国に保管されるか。法規制の適用が変わる |
| 可用性 | 障害時の最大許容停止時間（→ [15-1 サービスマネジメント](../15-service-management/15-1-サービスマネジメント.md) のSLA） |
| 移行性 | 他の事業者や自社環境に戻せるか（ベンダロックインの回避） |
| セキュリティ | 認証連携、暗号化、監査ログの取得（→ [11-5 セキュリティ実装技術](../11-security/11-5-セキュリティ実装技術.md)） |

**「所有から利用へ」の転換は、統制を自社の外に出すことを意味する**。便利さと引き換えに、自分ではどうにもできない部分が増える。この認識が、クラウド利用の検討で最初に押さえるべき点になる。

## この章のまとめ

- 提供形態は**所有（オンプレミス）から利用（クラウド）へ**。**ホスティングは事業者のサーバを借り、ハウジングは自社サーバの置き場所を借りる**。
- **プロビジョニングは、需要を予想して資源を計画的に調達し、要求に応じて提供すること**。クラウドの「すぐ使える」を支える仕組みである。
- **ソリューションビジネスは顧客の課題の特定から始まる**。製品知識だけでなく業界・業務の理解が要る。
- クラウド利用では、**事業者の継続性、データの所在、移行性**といった、自社では統制できない要素の評価が重要になる。
