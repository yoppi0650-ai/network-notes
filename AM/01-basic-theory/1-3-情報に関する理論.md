# 1-3 情報に関する理論

情報をどう表現し、どう守り、どう扱うかの理論を扱う。符号理論（誤り検出・訂正、データ圧縮）、オートマトン、そして人工知能（機械学習）が主な題材である。

この章の中心は**符号理論**である。情報に冗長なビットを付け加えることで、化けた情報を検出し、さらには訂正できる──この考え方が、メモリのECC（→ [3-2 メモリ](../03-computer-components/3-2-メモリ.md)）から通信の誤り制御（→ [10-2 データ通信と制御](../10-network/10-2-データ通信と制御.md)）まで、あらゆる場所で使われている。逆に、冗長を取り除いて情報を小さくするのがデータ圧縮であり、両者は同じ理論の表と裏にあたる。

午前Iの問2前後から出題される。16年で12問と、分野1のなかで最も出題が多い。近年は**AI・機械学習**の出題が加わっている。

## 1. 誤り検出の符号

情報に**冗長ビット**を付け加えることで、誤りを検出したり訂正したりできる。付け加える量が多いほど強力になるが、その分だけ効率は落ちる。

| 符号 | 冗長ビット | できること |
| --- | --- | --- |
| パリティチェック | 1ビット | 奇数個の誤りの検出 |
| 水平垂直パリティ | 行＋列 | **1ビットの誤り訂正** |
| **CRC** | 数ビット〜数十ビット | **バースト誤り（連続した誤り）の検出**。訂正はできない |
| **ハミング符号** | $\log$ オーダ | **1ビットの誤り訂正＋2ビットの誤り検出** |

### 1.1 パリティチェック

データ中の1の個数が偶数（または奇数）になるように、1ビットを付加する。受信側で1の個数を数え、パリティが合わなければ誤りと判定する。

単純だが、**偶数個のビットが同時に化けると検出できない**。2ビット化ければ1の個数の偶奇は元に戻ってしまう。

### 1.2 CRC

**CRC（Cyclic Redundancy Check、巡回冗長検査）**は、

> **送信側では、生成多項式を用いて検査対象のデータから検査用のデータを作り、これを検査対象のデータに付けて送信する。**

受信側は、受け取ったデータ全体（検査用データを含む）を**同じ生成多項式で割り**、**余りが0になれば誤りがなかった**と判断する。

正確に押さえるべき点を挙げる。

| 誤った記述 | 正しくは |
| --- | --- |
| 検査用のデータは1ビットの値である | **数ビット〜数十ビット**。CRC-32なら32ビット |
| 受信側では、付加されてきた検査用のデータで検査対象のデータを割る | **割るのは生成多項式**であって検査用データではない |
| 送信側と受信側では、異なる生成多項式が用いられる | **同じ生成多項式**を使う。違えば検査が成立しない |

CRCが**バースト誤りに強い**のは、生成多項式による除算が、連続したビット列の変化を敏感に捉えるように設計されているからである。通信路での誤りは単発よりも連続して起きやすい（ノイズは一瞬ではなく一定時間続く）ため、この性質が実用上きわめて有効になる。イーサネットのFCS（→ [10-1 ネットワーク方式](../10-network/10-1-ネットワーク方式.md)）やHDLCのFCS（→ [10-2](../10-network/10-2-データ通信と制御.md)）はいずれもCRCである。

**CRCは検出専用で訂正はできない**。訂正したければ再送を要求する（ARQ）か、次節のハミング符号のような訂正符号を使う。

> **出題** CRC: H21午前I問2

## 2. ハミング符号による誤り訂正

**ハミング符号**は、複数のパリティビットを重ね合わせることで、**誤ったビットの位置まで特定して訂正できる**符号である。**4回出題されている**頻出テーマである。

### 2.1 仕組み

複数のパリティ検査式を、**検査するビットの組合せが互いに重なり合うように**設計する。1ビットが化けると、そのビットを含む検査式だけが不成立になる。どの検査式が不成立かの組合せから、化けたビットの位置が一意に決まる。

### 2.2 例題1：検査式から位置を求める

> 符号長7ビット、情報ビット数4ビットのハミング符号による誤り訂正を次のとおりとする。受信した符号語 $x_1x_2x_3x_4x_5x_6x_7$ に対して
>
> $c_0 = x_1 + x_3 + x_5 + x_7$
> $c_1 = x_2 + x_3 + x_6 + x_7$
> $c_2 = x_4 + x_5 + x_6 + x_7$
> （いずれも mod 2）
>
> を計算し、少なくとも一つが0でない場合は $i = c_0 + c_1 \times 2 + c_2 \times 4$ を求めて、左から $i$ ビット目を反転する。受信した符号語が **1000101** であった場合、誤り訂正後の符号語はどれか。

受信語を割り当てる。$x_1=1, x_2=0, x_3=0, x_4=0, x_5=1, x_6=0, x_7=1$。

$$ c_0 = 1 + 0 + 1 + 1 = 3 \equiv 1 \pmod 2 $$
$$ c_1 = 0 + 0 + 0 + 1 = 1 $$
$$ c_2 = 0 + 1 + 0 + 1 = 2 \equiv 0 \pmod 2 $$

$$ i = 1 + 1 \times 2 + 0 \times 4 = 3 $$

左から3ビット目（$x_3 = 0$）を反転して1にする。

$$ 1000101 \ \rightarrow \ \mathbf{1010101} $$

**この方式の巧妙さ**は、$i$ の計算にある。$c_0, c_1, c_2$ を2進数の各桁とみなすと、不成立だった検査式の組合せがそのまま誤りビットの位置を表す数になるよう、検査式が設計されている。だから計算した $i$ が答えそのものになる。

### 2.3 例題2：検査式の交わりから位置を特定する

> 4ビットの情報ビット $x_1 x_2 x_3 x_4$ に対して
>
> $(x_1+x_2+x_3+x_5) \bmod 2 = 0$
> $(x_1+x_2+x_4+x_6) \bmod 2 = 0$
> $(x_2+x_3+x_4+x_7) \bmod 2 = 0$
>
> を満たす冗長ビット $x_5 x_6 x_7$ を付加する。受信符号 $y_1 \cdots y_7 = \mathbf{1100010}$ のとき、正しい情報ビットはどれか。

$y_1=1, y_2=1, y_3=0, y_4=0, y_5=0, y_6=1, y_7=0$ を各式に代入する。

| 式 | 計算 | 結果 |
| --- | --- | --- |
| $y_1+y_2+y_3+y_5$ | $1+1+0+0 = 2$ | **0**（成立） |
| $y_1+y_2+y_4+y_6$ | $1+1+0+1 = 3$ | **1**（不成立） |
| $y_2+y_3+y_4+y_7$ | $1+0+0+0 = 1$ | **1**（不成立） |

**第2式と第3式だけが不成立**である。したがって誤ったビットは、

- 第2式に**含まれる**：$x_1, x_2, x_4, x_6$
- 第3式に**含まれる**：$x_2, x_3, x_4, x_7$
- 第1式には**含まれない**：$x_4, x_6, x_7$（$x_1, x_2, x_3, x_5$ を除く）

3条件すべてを満たすのは **$x_4$** だけである。$y_4 = 0$ を反転して1にすると、情報ビットは $x_1x_2x_3x_4 = \mathbf{1101}$ となる。

**解き方の定石**は、**「不成立の式すべてに含まれ、成立した式には含まれないビット」を探す**ことである。各式に含まれるビットの一覧を書き出して突き合わせれば機械的に求まる。

### 2.4 例題3：排他的論理和による表現

> $X_1, X_2, X_3, X_4$ の4ビットに冗長ビット $P_3, P_2, P_1$ を付加した **$X_1 X_2 X_3 P_3 X_4 P_2 P_1$** を考える。冗長ビットは
>
> $X_1 \oplus X_3 \oplus X_4 \oplus P_1 = 0$
> $X_1 \oplus X_2 \oplus X_4 \oplus P_2 = 0$
> $X_1 \oplus X_2 \oplus X_3 \oplus P_3 = 0$
>
> となるように決める。ハミング符号 **1110011** の誤りビットを訂正したものはどれか。

並び順に注意して割り当てる。$X_1=1, X_2=1, X_3=1, P_3=0, X_4=0, P_2=1, P_1=1$。

| 式 | 計算 | 結果 |
| --- | --- | --- |
| $X_1 \oplus X_3 \oplus X_4 \oplus P_1$ | $1 \oplus 1 \oplus 0 \oplus 1 = 1$ | **不成立** |
| $X_1 \oplus X_2 \oplus X_4 \oplus P_2$ | $1 \oplus 1 \oplus 0 \oplus 1 = 1$ | **不成立** |
| $X_1 \oplus X_2 \oplus X_3 \oplus P_3$ | $1 \oplus 1 \oplus 1 \oplus 0 = 1$ | **不成立** |

**3式すべてが不成立**なので、誤りビットは3式すべてに含まれるものである。$X_1$ だけが全式に登場するので、$X_1$ を反転する。

$$ 1110011 \ \rightarrow \ \mathbf{0110011} $$

3つの例題はいずれも同じ原理に基づいている。**「どの検査式が不成立か」から「どのビットが化けたか」を逆算する**という手順を押さえれば、式の書き方や並び順が変わっても対応できる。

> **出題** ハミング符号: H23午前I問2、H24午前I問2、R4午前I問1、R6午前I問2 ｜ メモリの誤り制御: H30午前I問5

## 3. 水平垂直パリティ

> 16ビットのデータを $4 \times 4$ の正方形状に並べ、**行と列にパリティビットを付加する**ことによって、何ビットまでの誤りを訂正できるか。

答えは **1ビット**である。

1ビットが化けると、**その行のパリティと、その列のパリティの両方が不成立**になる。行と列の交点が特定できるので、そのビットを反転すれば訂正できる。

```
      列1 列2 列3 列4  P
行1 │  1   0   0   0 │ 1
行2 │  0   1  [X]  0 │ 0   ← この行のパリティが不成立
行3 │  0   0   1   0 │ 1
行4 │  1   1   0   1 │ 1
  P │  0   0   0   1 │
             ↑ この列のパリティが不成立 → 交点が誤りビット
```

2ビット以上が化けると訂正はできない。同じ行の2ビットが化ければ行パリティは元に戻り、位置の特定ができなくなる。**検出はできるが訂正はできない**、というのが2ビット以上の場合である。

水平垂直パリティは単純な仕組みで1ビット訂正を実現するが、**冗長ビットの数が多い**（16ビットに対して9ビット）。同じ1ビット訂正を、ハミング符号なら少ない冗長ビットで実現できる。実用でハミング符号が選ばれるのはこの効率の差による。

> **出題** 水平垂直パリティ: H27午前I問2

## 4. データ圧縮と可変長符号

誤り訂正が**冗長を足す**技術なら、データ圧縮は**冗長を削る**技術である。

### 4.1 可変長符号と語頭条件

出現頻度の高い文字に短い符号を、低い文字に長い符号を割り当てれば、全体の長さを縮められる。これが**可変長符号**の考え方で、**ハフマン符号**が代表例である。

ただし、可変長にすると**区切りが分からなくなる**という問題が生じる。これを解決するのが**語頭条件（プレフィックス条件）**である。

> **どの符号も、他の符号の先頭部分（接頭辞）になっていないこと。**

この条件を満たせば、ビット列を先頭から読んでいって符号と一致した瞬間に区切ってよい。区切り記号を入れずに一意に復号できる。

**例題：一意に復号でき、最も短くなる符号はどれか**

> a, b, c, d の出現頻度はそれぞれ 50%、30%、10%、10% である。

| | a | b | c | d | 語頭条件 |
| --- | --- | --- | --- | --- | --- |
| ア | 0 | 1 | 00 | 11 | **違反**（`0` が `00` の接頭辞、`1` が `11` の接頭辞） |
| イ | 0 | 01 | 10 | 11 | **違反**（`0` が `01` の接頭辞） |
| **ウ** | **0** | **10** | **110** | **111** | **満たす** |
| エ | 00 | 01 | 10 | 11 | 満たす（固定長） |

まず語頭条件でアとイが脱落する。残るウとエの平均符号長を比べる。

$$ \text{ウ} = 1 \times 0.5 + 2 \times 0.3 + 3 \times 0.1 + 3 \times 0.1 = 0.5 + 0.6 + 0.3 + 0.3 = \mathbf{1.7} $$
$$ \text{エ} = 2 \times (0.5+0.3+0.1+0.1) = \mathbf{2.0} $$

**ウが最短**である。頻度の高い a に1ビットを割り当てたことが効いている。

**解き方の手順**は、**まず語頭条件で候補を絞り、残った候補の平均符号長（符号長 × 出現確率の総和）を比べる**ことである。

### 4.2 圧縮率の計算

> 四つのアルファベットa〜dが2ビットの固定長符号で符号化されている。出現確率と可変長符号が表のとおりのとき、**変換前に対する変換後のビット列の長さの比**はおよそ幾つか。

| アルファベット | a | b | c | d |
| --- | --- | --- | --- | --- |
| 出現確率 | 40% | 30% | 20% | 10% |
| 可変長符号 | 0 | 10 | 110 | 111 |

変換後の平均符号長は

$$ 1 \times 0.4 + 2 \times 0.3 + 3 \times 0.2 + 3 \times 0.1 = 0.4 + 0.6 + 0.6 + 0.3 = 1.9\ \text{ビット} $$

変換前は固定長2ビットなので、比は

$$ \frac{1.9}{2} = \mathbf{0.95} $$

圧縮できたのはわずか5%である。出現確率の偏りが小さいと圧縮効果も小さい、という関係がここに現れている。**情報理論的には、偏りが大きいほど（エントロピーが小さいほど）圧縮できる**。すべての文字が等確率なら、可変長にしても縮まらない。

> **出題** 可変長符号: H22午前I問2 ｜ 圧縮率の計算: H29午前I問2

## 5. オートマトン

**有限オートマトン**は、有限個の**状態**をもち、入力記号を読むたびに状態を遷移する計算モデルである。文字列が特定のパターンに合致するかを判定する（受理する）のに使われる。

### 5.1 例題：状態の意味を読み取る

> 入力記号の集合が $\{0, 1\}$、状態集合が $\{a, b, c, d\}$ である有限オートマトンの状態遷移表が次のとおりである。長さ3以上の任意のビット列を左から順に読み込んで、**最後が 110 で終わっている**ものを受理するには、どの状態を受理状態とすればよいか。

| 状態 | 入力0 | 入力1 |
| --- | --- | --- |
| a | a | b |
| b | c | d |
| c | a | b |
| d | c | d |

**解き方は、受理したい文字列を実際に読ませてみる**ことである。初期状態を $a$ として `110` を読む。

$$ a \xrightarrow{1} b \xrightarrow{1} d \xrightarrow{0} \mathbf{c} $$

`110` を読み終えたときの状態は **$c$** である。したがって受理状態は $c$ になる。

念のため、$c$ が「直前が110で終わっている」状態を正しく表しているか確かめる。

- $c$ から `0` を読むと $a$ へ（`1100` は110で終わらない → 受理しない）✓
- $c$ から `1` を読むと $b$ へ（`1101` は110で終わらない → 受理しない）✓
- $d$（11以上が続いている状態）から `0` を読むと $c$ へ（`110` で終わる → 受理）✓

各状態の意味を読み取ると次のようになる。

| 状態 | 意味 |
| --- | --- |
| a | 直前が `0` で終わり、`11` の途中でない |
| b | 直前が `1` が1個 |
| d | 直前が `1` が2個以上 |
| **c** | **直前が `110` で終わっている** |

**状態遷移表の問題は、「各状態が何を覚えているか」を言葉にできると確実に解ける**。この考え方は通信プロトコルの状態遷移（→ [10-3 通信プロトコル](../10-network/10-3-通信プロトコル.md) のTCP状態遷移）や、状態遷移図による設計（→ [12-2 設計](../12-system-development/12-2-設計.md)）にも共通する。

> **出題** 有限オートマトン: H28午前I問2

## 6. 人工知能と機械学習

近年、AI・機械学習が基礎理論の分野から出題されるようになっている。

### 6.1 学習の3分類

| 分類 | 内容 | 代表的な手法 |
| --- | --- | --- |
| **教師あり学習** | **正解のラベルを付けたデータ**からモデルを作る | 回帰分析、分類（パターン認識） |
| **教師なし学習** | **正解のラベルを付けないデータ**からモデルを作る | **クラスタリング**、次元削減 |
| **強化学習** | **一定の環境の中で試行錯誤を行い、行動に報酬を与える**ことで学習する | — |

**教師なし学習で用いられる手法**として出題されたのは、

> **データ同士の類似度を定義し、その定義した類似度に従って似たもの同士は同じグループに入るようにデータをグループ化するクラスタリング**

である。**正解を与えずに、データの構造そのものから グループを見つける**のが教師なし学習の特徴になる。顧客をいくつかのセグメントに分ける、といった分析に使われる（→ [22-2 業務分析・データ利活用](../22-corporate-activities/22-2-業務分析-データ利活用.md)）。

誤答として並ぶ手法を確認する。

| 記述 | 分類 |
| --- | --- |
| 既存データ間に分離境界を定め、新たなデータがどのグループに属するかを判別するパターン認識 | **教師あり学習**（分類） |
| 乱数を使って疑似データを作り、数値計算で解を推定するモンテカルロ法 | 機械学習ではない数値計算手法 |
| 時系列データに曲線の当てはめを行い、補完や未来予測を行う回帰分析 | **教師あり学習**（回帰） |

**「グループ分けの正解が与えられているか」**が分類とクラスタリングの境目である。既存のグループに当てはめるのが分類（教師あり）、グループ自体を見つけるのがクラスタリング（教師なし）になる。

### 6.2 過学習

**過学習（オーバーフィッティング）**は、**訓練データに適合しすぎて、未知のデータに対する予測精度が落ちる**現象である。訓練データのノイズや偶然の特徴まで覚え込んでしまうために起きる。

**過学習が疑われたときの解消方法**として適切なのは、

> **精度を高めるために、元の訓練データに加工を施し、訓練データの量を増やす。**

これが**データ拡張（データオーグメンテーション）**である。画像なら回転・反転・明るさの変更などを施して水増しする。訓練データが増えれば、偶然の特徴に引きずられにくくなる。

誤答として並ぶ記述は、いずれも**過学習を悪化させる**ものである。

| 記述 | なぜ悪化するか |
| --- | --- |
| 訓練したときと同じ精度を出すために、訓練データをテストデータとして使用する | **汎化性能を測れなくなる**。過学習していても高精度に見えてしまう |
| 予測した結果に近づけるために、モデルをより複雑にする | **複雑なモデルほど過学習しやすい** |
| 多くの未知のデータに対して予測できるように、汎化性能を下げる | **逆**。上げるべきである |

過学習への対策には、データ拡張のほか、**正則化**（モデルの複雑さに罰則を与える）、**交差検証**（データを分割して汎化性能を測る）、**早期打切り**（学習を途中で止める）などがある。いずれも「訓練データへの適合」と「未知データへの対応」のバランスを取るための手段である。

> **出題** 教師なし学習: R1午前I問3 ｜ 過学習: R7午前I問2

## この章のまとめ

- **CRCは生成多項式で検査データを作り、受信側は同じ多項式で割って余りが0かを見る**。バースト誤りの**検出**に強いが訂正はできない。
- **ハミング符号は「どの検査式が不成立か」から誤りビットの位置を逆算する**。「不成立の式すべてに含まれ、成立した式には含まれないビット」を探す。
- **水平垂直パリティで訂正できるのは1ビットまで**。行と列のパリティの交点が誤り位置になる。
- 可変長符号は**語頭条件を満たすことが一意復号の条件**。候補を語頭条件で絞ってから、**平均符号長（符号長 × 出現確率の総和）**を比べる。
- 有限オートマトンの問題は、**受理したい文字列を実際に読ませて到達する状態**を求める。各状態が何を覚えているかを言葉にすると確実になる。
- 機械学習は **教師あり（正解ラベルあり）、教師なし（クラスタリング）、強化学習（試行錯誤と報酬）**。**過学習の解消にはデータ拡張**が有効で、モデルの複雑化や汎化性能の低下は逆効果である。
