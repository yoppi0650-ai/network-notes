# 7-1 ユーザインタフェース

人とシステムの接点を扱う。とりわけ、**どんな人でも使えるようにする**という観点が出題の中心になる。

この分野の根底にある問いは、「**利用者とは誰か**」である。開発者は無意識に「自分と同じように見え、聞こえ、操作できる人」を想定してしまう。しかし実際の利用者には、視覚に障害のある人、高齢者、色の区別がつきにくい人、片手しか使えない状況の人が含まれる。アクセシビリティとは、この想定の狭さを正す取り組みである。

午前Iの問9前後、午前IIの問24前後から出題される。16年で3問。

## 1. アクセシビリティとユーザビリティ

| 用語 | 意味 |
| --- | --- |
| **アクセシビリティ** | **多様な人が利用できること**。使える／使えないの問題 |
| **ユーザビリティ（使用性）** | **使いやすいこと**。効率・満足度の問題 |
| ユニバーサルデザイン | 最初からできるだけ多くの人が使えるように設計すること |

**アクセシビリティは「使えるかどうか」、ユーザビリティは「使いやすいかどうか」**という段階の違いがある。使えない人がいる状態を解消するのが前者、使える人がより快適に使えるようにするのが後者である。

ユーザビリティは品質特性の一つ「使用性」として定義されている（→ [12-1 システム・ソフトウェア要件定義](../12-system-development/12-1-システム-ソフトウェア-要件定義.md)）。さらに、使いやすさを超えて**利用前後を含む体験全体**をどう設計するかは [7-2 UX/UIデザイン](7-2-UX-UI-デザイン.md) で扱う。

## 2. Webアクセシビリティの設計方針

> **Webアクセシビリティに配慮した画面の設計方針**のうち、適切なものはどれか。

答えは、

> **仮名入力欄の前には、「フリガナ（カタカナで入力）」のように、仮名の種類も明記する。**

**「ふりがな」「フリガナ」という表記の違いだけで入力すべき文字種を伝える**のは、視覚的な慣習に頼った設計である。音声読み上げでは両者を区別できず、そもそもこの慣習を知らない利用者もいる。**明示的に言葉で伝える**ことが、誰にでも伝わる設計になる。

誤答として並ぶ3つは、いずれもアクセシビリティを**損なう**設計である。

| 記述 | なぜ不適切か |
| --- | --- |
| **head要素の中のtitle要素を同一にして、各ページに同じ表題を付ける** | **ページを区別できなくなる**。音声読み上げやタブ一覧では表題が唯一の手がかりになることが多い。ページごとに内容を表す固有の表題を付けるべきである |
| **確認は緑、取消しは赤などのように、共通に使用されるボタンは色だけで判別できるようにする** | **色だけに頼ってはならない**。色覚特性によって区別できない利用者や、白黒印刷・画面設定によって色が伝わらない場合がある。**色に加えて、文字・形・位置でも区別できるようにする** |
| **ハイパリンク及びボタンは、操作性を良くするために隣り合うものとの間隔を狭くとる** | **間隔が狭いと誤操作しやすい**。手の震えがある人、タッチ操作の人には特に押しにくくなる。十分な間隔を確保するのが正しい |

3つの誤答には共通点がある。**「特定の条件がそろった利用者」を暗黙に前提にしている**ことである。目が見え、色が区別でき、細かい操作ができる──この前提が崩れた瞬間に使えなくなる設計を避ける、というのがアクセシビリティの考え方である。

> **出題** Webアクセシビリティ: H21午前I問9

## 3. JIS X 8341-1 の目的

**JIS X 8341-1:2010**（高齢者・障害者等配慮設計指針 — 情報通信における機器、ソフトウェア及びサービス — 第1部：共通指針）を適用する目的は、

> **多様な人々に対して、利用の状況を理解しながら、多くの個人のアクセシビリティ水準を改善すること。**

ここで押さえるべきは、規格が**何を目指していないか**である。誤答がそれを示している。

| 記述 | なぜ誤りか |
| --- | --- |
| **全ての個人に対して、等しい水準のアクセシビリティを達成する** | **「全ての個人に等しい水準」は目指していない**。人によって必要な配慮は異なるので、一律の水準を定めること自体が現実的でない |
| 人間工学に関する規格が要求する水準より高いアクセシビリティを提供する | 他の規格との水準比較を目的としていない |
| **平均的能力をもった人々に対して、標準的なアクセシビリティが達成される** | **「平均的能力」を前提にすること自体が、この規格の問題意識と正反対**である |

規格の立場は**「全員に同じものを」でも「平均的な人に合わせて」でもなく、「多様さを理解したうえで、改善できるところを改善する」**という現実的なものである。完璧なアクセシビリティは達成できなくても、利用の状況を理解すれば改善できる点は必ずある、という考え方に立っている。

Webコンテンツに特化した規格としては **JIS X 8341-3**（WCAGに対応）があり、適合レベルをA、AA、AAAで表す。

> **出題** JIS X 8341-1: H29午前I問8

## 4. 使用性の向上

> **ソフトウェアの使用性を向上させる施策**として、適切なものはどれか。

答えは、

> **オンラインヘルプを充実させ、利用方法を理解しやすくする。**

**使用性（ユーザビリティ）は「理解しやすさ、使いやすさ」**に関わる品質である。ヘルプの充実は、利用者が機能を理解する助けになるので使用性の向上にあたる。

誤答は、いずれも**別の品質特性**の向上施策である（→ [12-1 システム・ソフトウェア要件定義](../12-system-development/12-1-システム-ソフトウェア-要件定義.md)）。

| 記述 | 向上する品質特性 |
| --- | --- |
| 外部インタフェースを見直し、連携できる他システムを増やす | **機能性**（相互運用性） |
| 機能を追加し、業務においてシステムが利用できる範囲を拡大する | **機能性**（合目的性） |
| ファイルの複製を分散して配置し、障害によるシステム停止のリスクを減らす | **信頼性**（障害許容性） |

**「機能が増える」ことと「使いやすくなる」ことは別**である。むしろ機能が増えれば操作は複雑になり、使用性は下がりうる。この区別が設問の狙いである。

> **出題** ソフトウェアの使用性: H29午前II問24

## 5. 画面設計の基本

出題はされていないが、設計の指針として押さえておきたい点を挙げる。

| 観点 | 指針 |
| --- | --- |
| 一貫性 | 同じ意味の操作は、どの画面でも同じ手順・同じ位置にする |
| エラーの予防 | 誤った入力をそもそも受け付けない（→ [4-1 システムの構成](../04-system-components/4-1-システムの構成.md) のフールプルーフ） |
| エラーからの回復 | 何が問題でどうすればよいかを、具体的に伝える |
| 可逆性 | 取消し（アンドゥ）ができるようにする |
| 負担の軽減 | 利用者に記憶を強いず、選択肢を示す |

**エラーメッセージは「何が起きたか」ではなく「どうすればよいか」を伝える**ことが重要である。「エラーが発生しました」では利用者は何もできない。「郵便番号はハイフンなしの7桁で入力してください」であれば、次の行動が分かる。これは [4-1](../04-system-components/4-1-システムの構成.md) で見たフールプルーフの実例そのものでもある。

入力フォームの設計では、**入力形式を利用者に合わせる**ことも効く。日付を「YYYYMMDD形式で入力」と求めるより、カレンダーから選ばせるほうが誤りも手間も減る。

## この章のまとめ

- **アクセシビリティは「使えるか」、ユーザビリティは「使いやすいか」**。
- Webアクセシビリティでは、**色だけで判別させない、ページごとに固有の表題を付ける、操作対象の間隔を十分にとる**。暗黙に特定の利用者を前提にした設計を避ける。
- **JIS X 8341-1 が目指すのは「全員に等しい水準」でも「平均的な人向け」でもなく、「多様さを理解したうえでの改善」**である。
- **使用性の向上はヘルプの充実など「理解しやすさ」に関わる施策**。機能追加や冗長化は別の品質特性の話である。
