# 13-2 知的財産適用管理

ソフトウェア開発において、**権利が誰に帰属し、何をしてよいか**を扱う。

技術そのものではないが、開発の現場では避けて通れない。他社のソフトウェアをどこまで調べてよいか、委託して作らせたプログラムは誰のものか、自社技術を特許にすべきか秘密にすべきか──これらの判断を誤ると、完成したシステムが使えなくなったり、賠償責任を負ったりする。

午前Iの問17前後から出題される。16年で5問。法律そのものの条文は [23-1 知的財産権](../23-legal-affairs/23-1-知的財産権.md) で扱い、本章では**開発管理の観点**から整理する。

## 1. ソフトウェアに関わる権利

| 権利 | 保護するもの | 取得方法 |
| --- | --- | --- |
| **著作権** | **表現**（ソースコード、画面デザイン、ドキュメント） | 創作した時点で**自動的に発生**（無方式主義） |
| **特許権** | **技術的思想（アイデア、アルゴリズム）** | 出願・審査・登録が必要 |
| 営業秘密（不正競争防止法） | 秘密として管理された有用な情報 | 秘密管理性・有用性・非公知性の3要件を満たすこと |

**著作権は「表現」を、特許権は「アイデア」を保護する**という違いが基本になる。同じ機能を実現するプログラムでも、コードを書き写せば著作権侵害だが、仕様を見て独自に書き直せば著作権侵害にはならない。一方、そのアルゴリズムが特許になっていれば、独自に書いても特許侵害になりうる。

## 2. 著作権の帰属

### 2.1 委託開発での帰属

**原則として、著作権は実際に創作した者（法人であればその法人）に帰属する**。費用を出した側ではない。

> 組込み機器用のソフトウェアを開発委託する契約書に**開発成果物の著作権の帰属先が記載されていない**場合、委託元であるソフトウェア発注者に発生するおそれがある問題はどれか。ここで、ソフトウェアは委託先が全て自主開発するものとする。

答えは、

> **開発成果物を、委託元で開発する別のソフトウェアに適用できなくなる。**

契約に定めがなければ、**著作権は開発した委託先に残る**。委託元は成果物を「使う」ことはできても、**複製して別のソフトウェアに流用する**には委託先の許諾が要る。発注して費用を払ったのだから自分のものだ、という思い込みが通用しないのがこの論点である。

誤答として並ぶ記述を確認する。「ソースコードの公開が義務付けられる」（GPLなどのOSSライセンスの話 → [5-5 オープンソースソフトウェア](../05-software/5-5-オープンソースソフトウェア.md)）、「バイナリ形式でしか販売できなくなる」「アルゴリズムの特許を取得できなくなる」は、いずれも著作権の帰属とは別の問題である。

**対策は単純で、契約書に著作権の帰属を明記すること**である。「著作権は委託元に譲渡する」「委託先に留保し、委託元には無償の利用許諾を与える」など、取り決め方は複数ある。

### 2.2 請負と派遣での帰属

契約に定めがない場合の原始的な帰属は、契約形態で変わる。

| 形態 | 著作権の原始的帰属 |
| --- | --- |
| **請負** | **受注した会社（委託先）** |
| **派遣** | **派遣先の会社**（派遣社員は派遣先の指揮命令下で業務として開発するため） |

派遣の場合に派遣先に帰属するのは、**職務著作**の考え方による。法人の発意に基づき、その業務に従事する者が職務上作成した著作物は、法人が著作者になる。派遣社員は派遣先の指揮命令を受けて働くので、この条件を満たす。

この区別は [23-1 知的財産権](../23-legal-affairs/23-1-知的財産権.md) でも出題されている。

> **出題** 開発成果物の著作権の帰属: H26午前I問17

## 3. 著作権侵害になる行為

**プログラムの著作権侵害に該当する**のは、

> ソフトウェアハウスと使用許諾契約を締結し、**契約上は複製権の許諾を受けていない**が、使用許諾を受けたソフトウェアにはプロテクトがかけられていたので、**そのプロテクトを外し、バックアップのために複製した**。

ポイントは2つある。**複製権の許諾を受けていない**ことと、**技術的保護手段（プロテクト）を回避した**ことである。

著作権法には、プログラムの所有者が**バックアップのために複製できる**という規定がある。しかしこれは「必要と認められる限度」であり、**契約で複製権が許諾されていない場合や、プロテクトを回避する場合には認められない**。プロテクトの回避は、それ自体が別途問題になる行為でもある。

**侵害に該当しない**行為も押さえておく。

| 行為 | 侵害にならない理由 |
| --- | --- |
| **公開済プロトコルに基づいて、同等の機能をもつソフトウェアを独自に開発して販売した** | 著作権が保護するのは**表現**であり、機能やプロトコル仕様ではない。独自に書いたコードは別の著作物である |
| **他人のソフトウェアを正当な手段で入手し、逆コンパイルを行った** | 相互運用性の確保などの目的での解析は、一定の範囲で認められる |
| **複製及び改変する権利が付与されたソース契約の締結によって、許諾されたソフトウェアを改造して製品に組み込み、契約の範囲内で販売した** | **契約で許諾された範囲内**の行為である |

**「契約で許諾されているか」「表現を複製したか」**の2点が判断の軸になる。

> **出題** プログラムの著作権侵害: H24午前I問17

## 4. 使用許諾（ライセンス）

自社開発したソフトウェアを他社に使わせることを**使用許諾（ライセンス）**という。

> **使用許諾対象が特許で保護された技術を使っていないソフトウェアであっても、使用許諾することは可能である。**

これが正しい記述である。理由は [1. ソフトウェアに関わる権利](#1-ソフトウェアに関わる権利) で見たとおりで、**ソフトウェアには創作した時点で自動的に著作権が発生している**。特許を取っていなくても著作権者として使用を許諾できる。特許と使用許諾は別の話である。

誤答として並ぶ記述を確認する。

| 記述 | 誤りの理由 |
| --- | --- |
| 既に自社の製品に搭載して販売していると、ソフトウェア単体では使用許諾対象にできない | **製品に組み込んで販売していても、ソフトウェア単体を別途許諾できる**。権利者が自由に決められる |
| 既にハードウェアと組み合わせて特許を取得していると、ソフトウェア単体では使用許諾対象にできない | 特許の取得範囲と、著作物としての使用許諾は**別の問題**である |
| ソースコードを無償で使用許諾すると、無条件でオープンソースソフトウェアになる | **無償公開とOSSは別物**。OSSと呼ぶには再配布・改変の自由などOSI（Open Source Initiative）の定義を満たす必要がある（→ [5-5](../05-software/5-5-オープンソースソフトウェア.md)） |

全体を貫く考え方は、**権利者は自分の権利をどう行使するかを自由に決められる**ということである。「〜だから許諾できない」という制限は、よほど特殊な契約がない限り生じない。

> **出題** ソフトウェアの使用許諾: H28午前I問17、R1午前I問17

## 5. 特許化と秘匿の使い分け

新しい技術を開発したとき、**特許を出願する**か**ノウハウとして秘匿する**かという戦略的な判断がある。

| | 特許化 | 秘匿（営業秘密） |
| --- | --- | --- |
| 保護期間 | 出願から20年 | 秘密である限り無期限 |
| 公開 | **出願から1年6か月後に公開される** | 公開されない |
| 他社の独自開発 | 排除できる | 排除できない（独自に到達されたら終わり） |
| ライセンス収入 | 得やすい | 得にくい |
| 他社による解析 | 公開されるので解析は不要 | リバースエンジニアリングで判明する可能性 |

**特許化することが適切な技術的思想を特許出願せずにノウハウとして秘匿することが適切な例**は、

> **セキュリティ分野のソフトウェアで、アルゴリズムを公開したくない場合**

である。特許にすれば権利は守られるが、**その代償として技術内容が公開される**。セキュリティ製品では、アルゴリズムが公開されること自体が攻撃者に手がかりを与え、製品の価値を損ないうる。この場合は秘匿が合理的になる。

誤答として並ぶケースは、いずれも**秘匿が不適切な場合**である。

| ケース | 秘匿が不適切な理由 |
| --- | --- |
| 社内の秘密保持体制が構築できない場合 | **秘密として管理できなければ営業秘密として保護されない**。漏れたら何も残らない |
| 他社に積極的に技術使用許諾してライセンス収入を得たい場合 | ライセンスビジネスには**特許などの明確な権利**が必要 |
| リバースエンジニアリングによって技術が容易に明らかになる場合 | **秘匿してもすぐバレる**ので、特許で権利化すべき |

判断の軸は、**「秘密を保てるか」と「公開の代償を払う価値があるか」**の2点である。秘密を保てないなら特許、公開したくないなら秘匿、というのが基本の考え方になる。

> **出題** ノウハウの秘匿と特許出願: H23午前I問17

## この章のまとめ

- **著作権は表現を、特許権はアイデアを保護する**。著作権は創作時に自動発生する。
- **委託開発で契約に定めがなければ、著作権は開発した委託先に残る**。委託元は別のソフトウェアに流用できなくなるので、契約書に帰属を明記する。
- 著作権侵害になるのは**契約で許諾されていない複製**やプロテクトの回避。**公開仕様に基づく独自開発や、正当に入手した製品の解析は侵害にならない**。
- **特許がなくても著作権に基づいて使用許諾できる**。無償公開しただけではOSSにはならない。
- **特許化は公開が代償、秘匿は秘密を保てることが前提**。アルゴリズムを公開したくないなら秘匿、すぐ解析されるなら特許。
